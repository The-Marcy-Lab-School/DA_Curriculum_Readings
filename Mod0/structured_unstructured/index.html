What Shape Is This Data?

A public library runs a summer reading program for kids. At the end of summer, three files sit on the library's laptop: a sign-up sheet, the librarian's typed notes, and a file from the library's app. Each one is shaped differently, and the shape decides which tools work on it. So before you use a file, you check its shape.

3. Structured: the same columns in every row

Here is the sign-up sheet, opened with cat:

$ cat signups.csv
name,age,books_read,finished
Maya,9,12,True
Leo,11,7,False
Ava,8,15,True
Sam,10,4,False
Zoe,12,9,True

Every row has the same four fields in the same order. That makes it structured data: data organized into the same rows and columns every time, like a spreadsheet. The first line lists the column names. That fixed plan of field names, which every row follows, is the file's schema.

Because every row matches, you can count rows and compare columns with no surprises. A command called wc counts things in a file. wc -l counts lines.

Predict: what number does wc -l signups.csv print?

wc -l signups.csv
$ wc -l signups.csv
       6 signups.csv

What number does wc -l signups.csv print?

The line count includes the column-name line. Five kids signed up, plus one line of column names, makes six lines.

4. Unstructured: free-flowing text

The librarian's notes look nothing like the sign-up sheet:

$ cat notes.txt
Week 1 was busy. Maya asked for more graphic novels.
Leo said the summer list was too long, so we made a shorter one.
Week 3: Ava read 5 books in one week and wants a harder list.
Maya brought a friend to story time.

There are no columns. Each line is as long as the librarian made it. That's unstructured data: data with no fixed columns, like free text, photos, or audio. It still holds useful facts. You just can't pull them out by column.

Instead, you search the text. grep plus a word and a file name prints every line in that file that has the word.

Predict: what does grep Maya notes.txt print?

grep Maya notes.txt
$ grep Maya notes.txt
Week 1 was busy. Maya asked for more graphic novels.
Maya brought a friend to story time.

What does grep Maya notes.txt print?

5. Semi-structured: labels, but not the same every time

The app saves its entries in JSON. JSON is a common file format that stores each value next to a label, inside curly braces { }.

$ cat app_entries.json
[
  {"name": "Maya", "books_read": 12, "favorite_genre": "graphic novels"},
  {"name": "Leo", "books_read": 7},
  {"name": "Ava", "books_read": 15, "badges": ["Speed Reader", "Week 3 Star"]}
]

Every entry has a name and books_read. But Maya's also has favorite_genre, Ava's has a list of badges, and Leo's has neither. That in-between shape is semi-structured data: data with labels, where entries don't all have the same fields.

A classmate says app_entries.json is structured because it's "neat and labeled." What's the best reply?

A file's name can mislead you, too. A file ending in .csv might hold messy text. Open it and look before you decide.

6. Practice in a simulated terminal

This pretend terminal is open in the reading-program folder with all three files. Press Enter after each command.

  1. Type ls. You should see the three file names.
  2. Type cat signups.csv. Look for the same columns in every row.
  3. Type cat notes.txt. Look for the lack of columns.
  4. Type grep Ava notes.txt. You should see the one line about Ava.
  5. Type wc -w notes.txt. -w counts words, a better unit than rows for free text.
  6. Type cat app_entries.json. Look for which entries have extra labels.

8. Wrap-up

  • Structured data has the same columns in every row, following a schema. You can count rows and compare columns.
  • Unstructured data, like notes, photos, or audio, has no fixed columns. You search it instead.
  • Semi-structured data, like JSON, has labels, but entries don't all have the same fields. Open a file and look before you decide its shape.
