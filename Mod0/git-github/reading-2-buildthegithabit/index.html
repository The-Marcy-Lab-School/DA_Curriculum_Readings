1. Before Git: know where you are

Git commands act on the folder you are currently in. That makes basic terminal navigation a prerequisite.

pwd

What: print the current working directory.

Why: confirm where you are before running Git commands.

ls

What: list files and folders.

Why: see what is in the current directory.

cd

What: change directories.

Why: move into the project folder before using Git.

mkdir

What: create a directory.

Why: make a new project folder.

Common error: “not a git repository” often means you are in the wrong folder. Start by checking pwd and ls.

2. What each Git command is for

git init

Starts a Git repository in the current folder by creating Git's hidden history data.

git status

Reports the repository's current state: branch, staged changes, unstaged changes, and untracked files. Safe to run often.

git add FILE

Stages a file's changes for the next commit.

git commit -m "MESSAGE"

Saves the staged snapshot with a message describing what changed.

git diff

Shows unstaged changes compared with the last saved/staged state.

git remote add origin URL

Gives the local repository a named remote destination called origin.

git push -u origin main

Sends commits on your local main branch to the remote and records the upstream connection.

git log --oneline

Shows a compact one-line-per-commit history.

4. Debugging is part of the workflow

You run git status and see “not a git repository.” What should you check first?

You changed README.md, but git commit says there is nothing staged to commit. What likely step is missing?

When stuck, check status. git status is read-only and is often the fastest way to understand what Git thinks is happening.
