Git Saves the Story

Before you type Git commands in class, learn what Git is tracking, what GitHub adds, and why commits are more useful than a folder full of “final-final-v2” files.

Self-paced8–10 minutesConcept first
Read the explanation, then use the checks to test the mental model.

1. Imagine your project changes every day

You are helping a neighborhood group analyze tree-survey data. On Monday you clean column names. On Tuesday you fix a mistake. On Wednesday you add a chart. By Friday, someone asks: “What changed since Tuesday?”

Without version control

You might create files such as analysis_final.py, analysis_final2.py, and analysis_REALLY_final.py.

With Git

You keep one project and save meaningful snapshots of its history. Each snapshot can say what changed.

Git is version control. It records the history of a project so you can inspect what changed over time.

2. Git and GitHub are related—but not the same

Git

Runs on your computer. It tracks the history of files inside a repository.

Think: the history system.

GitHub

A website/service that can host a copy of a Git repository so you can share, collaborate, and keep a remote copy.

Think: a place the repository can live online.

You committed three changes locally but never pushed. Which statement is true?

3. Vocabulary you will hear in class

Repository

A project folder whose history Git is tracking.

Once a folder is a repository, Git can track snapshots and changes inside it.

Commit

A saved snapshot of the project at one point in time.

Commits create a readable history. A useful commit message explains the change.

Remote

A copy of the repository hosted somewhere else, such as GitHub.

A remote gives your local repository somewhere else to send commits.

4. The basic Git story

Git becomes easier when you see it as a sequence rather than a pile of commands.

1. INITTurn a folder into a Git repository.
2. ADDChoose changes for the next snapshot.
3. COMMITSave that snapshot with a useful message.
4. PUSHSend local commits to a remote such as GitHub.

Which order makes sense for a brand-new local project?

5. Staging is the “what goes in the next snapshot?” step

Editing a file does not automatically make that change part of your next commit. git add places selected changes into the staging area.

Working files

What currently exists in your project folder.

Staging area

The changes you have selected for the next commit.

Commit history

Snapshots you have already saved.

You edited two files but only want one in the next commit. What should you do?

6. Commit messages are for future humans

A commit message should tell someone what changed without forcing them to open every file.

Which message would be most useful six weeks from now?

Good habit: make the message specific enough that the history tells a story.
