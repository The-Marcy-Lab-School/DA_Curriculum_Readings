Git Saves the Story

Three neighbors are counting the trees on their street, and they keep the counts in one shared notes file. Over three weeks, one fixes a wrong count, one adds a new column, and one rewrites a confusing sentence. Each of them wants to know what changed and when. Git keeps that story for them. 1. One file, a history of saves

Without git, a shared file turns into copies named notes_final.md, notes_final_v2.md, and notes_REAL_final.md. Nobody can tell which copy has the fixed count. With git, the neighbors keep one file and save a series of checkpoints. Each checkpoint says what changed.

Each circle is a commit: a saved snapshot of the project at one moment, with a message that says what changed. The first three are also on GitHub, a website that keeps a copy. The newest one is only on one neighbor's laptop so far.

3. Start a repository

A repository, or "repo" for short, is a project folder whose history git is tracking. A folder becomes a repository when you run git init inside it. Git then keeps its history in a hidden folder called .git.

Predict: the neighbors' folder tree-notes holds one file, notes.md. Someone moves into the folder and runs this command. What happens?

git init
$ git init
Initialized empty Git repository in /Users/sam/tree-notes/.git/

What does git init do?

"Empty" means no snapshots are saved yet. Making a repository and saving a snapshot are separate steps.

4. Stage, then commit

Saving a snapshot takes two steps:

  1. git add notes.md puts that file's changes in the staging area. The staging area holds the changes you've picked for the next snapshot. Files you edited but didn't add stay out.
  2. git commit -m "message" saves everything in the staging area as one commit. The text in quotes after -m is the commit message.

git status tells you what's going on at any time, and it never changes anything. Its first line, On branch main, uses main, the name git gives your project's history by default.

Predict: after git add notes.md, what does git status say about notes.md?

git add notes.md git status
$ git add notes.md
$ git status
On branch main

No commits yet

Changes to be committed:
  (use "git rm --cached <file>..." to unstage)
	new file:   notes.md

What does git status say about notes.md?

The next command, git commit -m "Add first tree counts", saves the snapshot. Git answers with a short ID for the commit and what changed:

$ git commit -m "Add first tree counts"
[main (root-commit) d3d1ebd] Add first tree counts
 1 file changed, 4 insertions(+)
 create mode 100644 notes.md

A good message helps a neighbor six weeks from now who never saw the change.

5. Git, GitHub, and pushing

Git and GitHub are related, but they're not the same thing:

  • Git is a program on your own computer. It saves your project's history. It doesn't need the internet.
  • GitHub is a website that holds a copy of your repository, so other people can see it and work on it too.

The copy on GitHub is a remote: a copy of your repository kept somewhere else. To push is to send your saved commits up to the remote. Going the other way, to clone is to make your own copy of a repository that's already on GitHub, with its whole history.

The first push takes two commands. git remote add origin <url> tells git where the remote is and names it origin. Then git push -u origin main sends your commits there. The -u makes git remember the remote, so after the first time, plain git push works.

6. Try it yourself: a simulated terminal

This pretend terminal is open in /Users/sam/tree-notes, which holds notes.md. It answers the way real git does. Do one step at a time, and press Enter after each command.

  1. Type ls. You should see notes.md.
  2. Type git init. You should see "Initialized empty Git repository."
  3. Type git status. notes.md shows up as "untracked," which means git sees it but isn't saving it yet.
  4. Type git add notes.md. Nothing prints. That means it worked.
  5. Type git status again. Now notes.md is under "Changes to be committed."
  6. Type git commit -m "Add first tree counts". You should see the commit's short ID and message.
  7. Type git log. You should see your commit, newest first.
  8. Type git remote add origin https://github.com/you/tree-notes.git. Nothing prints.
  9. Type git push -u origin main. You should see your commit go up to GitHub.
The tree-notes folder is open. Start with step 1.
Something didn't work?

Read the message. "not a git repository" means git init hasn't run yet. "nothing to commit" means nothing is staged, so run git add notes.md first.

8. Wrap-up

  • A repository is a folder git tracks. git init starts one.
  • git add stages a change, and git commit -m saves the staged changes as a snapshot with a message.
  • Commits stay on your laptop until you push them to a remote like GitHub.
