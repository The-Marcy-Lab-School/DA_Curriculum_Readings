Who Can See This Variable?

A city parking office runs a small program that works out the fine for every ticket. One variable holds a fine only while one function runs, then it is gone. Another variable, set outside every function, lasts as long as the program runs. Mixing up these two kinds of variables is one of the most common early bugs in Python.

1. Concept overview

A clerk at the parking office writes one function to work out every fine:

def calculate_fine(base_fine, minutes_over): fine = base_fine + (minutes_over * 2) return fine ticket_total = calculate_fine(40, 10) print(ticket_total)
60

While calculate_fine runs, it has its own names: the parameters base_fine and minutes_over, and the variable fine created in its body. When return fine runs, the function hands back the value 60, and all three names stop existing. Only the returned value survives, stored in ticket_total. The part of a program where a name can be seen and used is its scope. A name created inside a function is a local variable: it exists only inside that function, and only while the function runs.

Not every variable works this way. daily_fine_cap is created outside every function, in the main body of the script. That makes it a global variable. It exists for the whole program, and any function can read it.

Why this matters: a function that reads a global variable works fine in the script where it was written. Copy it into a script without that global, and it raises a NameError. Reviewers and interviewers watch for this, because it is a common way that working code breaks when someone reuses it.

Where you're coming from, where this is headed: you already know how to define a function with parameters and hand a value back with return. This reading answers a new question: at a given line of code, which names exist, and which are already gone? Later ideas depend on this answer, such as functions that call other functions, and classes, where each object keeps its own copy of the same variable names.

6. A function can read a global without being told to

daily_fine_cap = 150 def calculate_fine(base_fine, minutes_over): fine = base_fine + (minutes_over * 2) return min(fine, daily_fine_cap) ticket_total = calculate_fine(90, 40) print(ticket_total)

What does calculate_fine need in order to run correctly here?

Key design idea: the call calculate_fine(90, 40) looks complete, but it hides something the function needs. Nothing in the call shows that daily_fine_cap must already exist outside the function.

7. Predict: the UnboundLocalError trap

A second function tries to count tickets as they are issued.

tickets_issued = 0 def issue_ticket(): tickets_issued = tickets_issued + 1 return tickets_issued print(issue_ticket())

Traceback (most recent call last):
  File "issue_ticket.py", line 7, in <module>
    print(issue_ticket())
          ~~~~~~~~~~~~^^
  File "issue_ticket.py", line 4, in issue_ticket
    tickets_issued = tickets_issued + 1
                     ^^^^^^^^^^^^^^
UnboundLocalError: cannot access local variable 'tickets_issued' where it is not associated with a value
Need a hint?

The line tickets_issued = tickets_issued + 1 assigns to tickets_issued. An assignment anywhere in a function decides that name's scope for the whole function.

14. How this shows up in interviews

Code reviewers see scope bugs often, especially functions that depend on a global variable. Interviewers know this, so a coding round may ask you to explain why a function stopped working after it was moved. The usual cause is section 6's problem: the function read a variable that existed only in the original script.

For software engineering roles, expect a follow-up: "How would you fix it?" A strong answer passes the value in as a parameter, as in sections 8 and 9. Adding global only hides the problem.

For data roles, the same trap shows up in notebooks. A function reads a setting or a table defined in another cell instead of taking it as an argument. You can't test that function on its own, and reviewers notice.

Interview-style question: "Is it ever reasonable for a function to read a global variable?" Which global is the safest one for a function to read?

16. Summary & critical thinking

This reading covered three ideas. A local variable is created each time its function runs and stops existing when the function returns. A global variable is created once and lasts for the whole program. Assigning to a name anywhere in a function makes it local for the whole function, which causes an UnboundLocalError if the function reads the name before assigning it.

New situation: a phone carrier's program has a function data_overage(gb_used). Inside it, a local variable extra_gb holds the data used past the plan's limit, and the function returns a charge. The program runs charge = data_overage(18), and the next line is print(extra_gb). What happens?
