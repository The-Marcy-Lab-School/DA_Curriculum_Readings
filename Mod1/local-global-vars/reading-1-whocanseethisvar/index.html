Who Can See This Variable?

A city parking ticket costs more the longer a car stays past its time. The city's program works out each ticket's cost with a function. Some variables in that program exist only while the function runs. Others last as long as the program runs. Knowing which is which prevents a common Python bug.

1. Where a name can be used

A parking ticket starts at a base cost, and it adds $2 for every minute a car stays past its time. Here is the city's function, ticket_price:

price_cap = 150 def ticket_price(base_cost, minutes_over): ticket_cost = base_cost + (minutes_over * 2) return ticket_cost ticket_total = ticket_price(40, 10) print(ticket_total)
60

While ticket_price runs, it has its own names: the parameters base_cost and minutes_over, and the variable ticket_cost created in its body. When return ticket_cost runs, the function hands back 60, and all three names stop existing. Only the returned value is kept, in ticket_total.

The part of a program where a name can be seen and used is the name's scope. A name created inside a function is a local variable: it exists only inside that function, and only while the function runs. A name created outside every function, like price_cap or ticket_total, is a global variable. It exists for the whole program, and any function can read it.

Mixing up these two kinds of names causes real bugs. A function that reads a global works in its own file, then breaks when someone copies it into a file that doesn't have that global. You already know how to write a function with parameters and return. This reading adds one question: at a given line, which names exist?

3. A local name is gone after the function returns

Each call to ticket_price goes through the same steps:

  1. Python makes a new, empty local scope for this call.
  2. Each parameter gets the value of its matching argument: base_cost gets 40, minutes_over gets 10.
  3. The body runs and creates ticket_cost, which is 60.
  4. return hands 60 back to the calling line.
  5. Every local name from this call stops existing.

Predict: ticket_outside.py adds one line at the end, print(ticket_cost). What happens when it runs?

def ticket_price(base_cost, minutes_over): ticket_cost = base_cost + (minutes_over * 2) return ticket_cost ticket_total = ticket_price(40, 10) print(ticket_total) print(ticket_cost)
60
Traceback (most recent call last):
  File "ticket_outside.py", line 7, in <module>
    print(ticket_cost)
          ^^^^^^^^^^^
NameError: name 'ticket_cost' is not defined. Did you mean: 'ticket_total'?

How to read an error message: when Python stops with an error, it prints a traceback.

  1. Read the last line first. It names the error and says what went wrong: NameError: name 'ticket_cost' is not defined. A NameError means the code used a name that doesn't exist at that line.
  2. Next, find the ^^^^ marks. They sit under the exact part of the code that failed.
  3. The line 7 part tells you which line of the file to look at. (<module> just means "the main part of the file, outside any function.")

Here Python even guesses what you meant: ticket_total, the global that holds the returned value.

4. A function can read a global, and that hides what it needs

The city never charges more than $150 for one ticket. ticket_cap_global.py reads that limit from the global price_cap.

New in this file: min() gives back the smaller of its values. min(170, 150) is 150.

Predict: what does ticket_price need in order to run correctly in ticket_cap_global.py?

price_cap = 150 def ticket_price(base_cost, minutes_over): ticket_cost = base_cost + (minutes_over * 2) return min(ticket_cost, price_cap) ticket_total = ticket_price(90, 40) print(ticket_total)
150

The call ticket_price(90, 40) looks complete, but nothing in it shows that price_cap must already exist. That causes trouble when the function moves to a new file.

A clerk copies late_fee from the main program into a new file. In the main program, fee_per_day was a global.

def late_fee(days_late): return days_late * fee_per_day print(late_fee(3))
Traceback (most recent call last):
  File "late_fee.py", line 4, in <module>
    print(late_fee(3))
          ~~~~~~~~^^^
  File "late_fee.py", line 2, in late_fee
    return days_late * fee_per_day
                       ^^^^^^^^^^^
NameError: name 'fee_per_day' is not defined

Why does the new file stop with this error?

The fix is to pass the value in as a parameter, so the call shows everything the function needs:

def late_fee(days_late, fee_per_day): return days_late * fee_per_day print(late_fee(3, 5))
15

5. Assigning inside a function makes a name local

Reading a global inside a function works. show_count.py reads the global tickets_issued and prints it:

tickets_issued = 0 def show_count(): print(tickets_issued) show_count()
0

Changing a global inside a function is different. Before a function runs, Python reads its whole body and follows one rule:

  1. Python looks for every name that appears on the left of an = in the body.
  2. Each of those names is local for the whole function, even on lines that come before the =.
  3. When the body runs, those names point only to the function's own local variables. The global with the same name is ignored.
  4. If the body reads one of those local names before giving it a value, Python stops with an UnboundLocalError: the local variable exists, but it has no value yet.

show_count has no = in its body, so tickets_issued stays the global there.

Predict: issue_ticket tries to add one to the count. Use the four-step rule. What happens when issue_ticket.py runs?

tickets_issued = 0 def issue_ticket(): tickets_issued = tickets_issued + 1 return tickets_issued print(issue_ticket())
Traceback (most recent call last):
  File "issue_ticket.py", line 7, in <module>
    print(issue_ticket())
          ~~~~~~~~~~~~^^
  File "issue_ticket.py", line 4, in issue_ticket
    tickets_issued = tickets_issued + 1
                     ^^^^^^^^^^^^^^
UnboundLocalError: cannot access local variable 'tickets_issued' where it is not associated with a value

Which fix for issue_ticket is easiest to check on its own and reuse in another file?

Here is the parameter version. Each call takes the current count and returns the new one, so the call shows everything the function uses:

tickets_issued = 0 def issue_ticket(count): return count + 1 tickets_issued = issue_ticket(tickets_issued) tickets_issued = issue_ticket(tickets_issued) print(tickets_issued)
2

7. Wrap-up

  • A local variable is created each time its function runs and stops existing when the function returns. Only the returned value is kept.
  • A global variable is created once, outside every function, and lasts for the whole program. A function that reads one hides what it needs, so passing a parameter is clearer.
  • Assigning to a name anywhere in a function makes it local for the whole function. Reading it before the assignment causes an UnboundLocalError.

New situation: when the city tows a car (pulls it away with a tow truck), the owner pays to get it back. The function tow_cost(days_held) creates a local variable storage_fee and returns the total. The program runs bill = tow_cost(3), and the next line is print(storage_fee). What happens?
