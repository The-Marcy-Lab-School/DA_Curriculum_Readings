Pick the Right Container

A community event app needs to remember a schedule, a fixed venue coordinate, attendee details, and the unique badge codes already scanned. One Python structure for everything? That would work—until the rules of the data start fighting the container.

About 15–18 minInteractiveNo setup requiredSaves locally
Goal: choose among list, tuple, dict, and set based on order, change, labels, and uniqueness.

1. Would you store everything the same way?

Workshop schedule

Order matters. Organizers may add or move sessions.

Venue coordinate

Latitude/longitude belong together and should stay fixed for this event.

Attendee profile

Named fields such as role, city, and check-in status.

Scanned badge codes

You only care whether a code has appeared before. Duplicates are useless.

Core idea: a data structure is a way to store multiple values, and each structure gives you different rules about order, change, lookup, and uniqueness.
