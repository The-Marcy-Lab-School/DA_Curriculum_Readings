Pick the Right Container

A food delivery app tracks four kinds of data every night: a driver's list of stops, finished orders that must never change, which driver has each order, and which customers already used a first-order coupon. Python has a container for each job, and each one follows its own rules.

1. Introduction

You already store one value in a variable and loop over a list. Real apps need to store many values at once, and they need different rules for different jobs. Picking the wrong container causes real bugs, like letting one customer use a first-order coupon twice. Interviewers often ask, "Which data structure would you use here, and why?"

3. Idea 1: lists change, tuples don't

A data structure is a container that holds many values under one name. Each kind has its own rules about order, repeats, and change.

Start with a driver's stops for the evening. The stops come in order, new stops get added at the end, and a stop can be swapped out. That is a list: an ordered collection, written with square brackets [ ], that you can change. A container you can change after you create it is mutable.

New in this file: stops.append("Oak Rd") adds "Oak Rd" to the end of the list stops. The dot means "use this list's own tool." stops[0] = "Main St" replaces the item at position 0.

Predict: what does the first print(stops) in route.py show?

stops = ["Elm St", "Pine Ave"] stops.append("Oak Rd") print(stops) stops[0] = "Main St" print(stops)
['Elm St', 'Pine Ave', 'Oak Rd']
['Main St', 'Pine Ave', 'Oak Rd']

Now a finished order. Once order D-5520 is dropped off at 7:42 PM, that record is final. If code changed it by mistake, the app's history would be wrong. That is a tuple: an ordered collection, written with parentheses ( ), that cannot change after it is created. A container you can't change is immutable.

New in this file: ("D-5520", "7:42 PM") is a tuple with two items. for code, time in finished: takes each tuple apart: the first item goes into code and the second into time. This is called unpacking.

4. Idea 2: a dictionary finds a value by its key

A customer asks, "Who has my order?" The app shouldn't check every order one by one. It should go straight from the order code to the driver's name. That is a dictionary, or dict: a collection of pairs, written with curly braces { }. Each pair has a key, the label you look up by, and a value, the data stored under that key. Here the key is the order code and the value is the driver's name. Each key appears only once.

New in this file: drivers["D-5521"] gives the value stored under the key "D-5521". drivers["D-5522"] = "Ari" adds a new pair. If the key already existed, it would replace that key's value instead.

Predict: what does print(drivers["D-5521"]) show?

drivers = {"D-5520": "Noor", "D-5521": "Sam"} print(drivers["D-5521"]) drivers["D-5522"] = "Ari" print(drivers)
Sam
{'D-5520': 'Noor', 'D-5521': 'Sam', 'D-5522': 'Ari'}

A dictionary jumps straight to the key, like a coat-check ticket, so a lookup is O(1): it does about the same work with 2 orders or 20,000. Dictionary keys must be things that can't change, like strings, numbers, and tuples. A list can't be a key.

You could keep order codes in one list and driver names in a second list, matched by position. That is risky: delete an item from one list and forget the other, and every pair after it is mismatched, with no error. A dictionary stores each key with its value, so they stay together.

5. Idea 3: a set keeps each value once

The app gives each customer one first-order coupon. It only needs to know who has used it already, and adding the same name twice should change nothing. That is a set: a collection of unique values with no fixed order. Like a dictionary key, each value in a set must be something that can't change. Checking in on a set is O(1), like a dictionary lookup.

7. Wrap-up

  • A list is ordered and can change. A tuple is ordered and can't change.
  • A dictionary stores key/value pairs and finds a value by its key in about one step.
  • A set keeps each value once. Use set() for an empty set, because {} is an empty dictionary.

New situation: the delivery app adds a menu. Each dish name needs its price. The kitchen's line of orders waiting to cook keeps changing. Which pairing fits best?

In interviews, name the rule that decides it: order, change, lookup by key, or no repeats.

As data grows, these containers start to nest: most real records are a list of dictionaries, one dictionary per row.
