1. The same step at every level

Recursion is when a function solves a problem by calling itself on a smaller piece of the same problem. You already repeat steps with a loop. Recursion repeats a step too, and it fits best when data sits inside more data of the same kind: folders inside folders, or replies to replies under a post. "Write a recursive function" is also a common interview question.

3. Base case and recursive case

Here is a small function that calls itself. Every working recursive function has two parts:

  • The base case is the branch where the function stops calling itself and returns. In countdown, that's the if n == 0: branch.
  • The recursive case is the branch that does a small piece of work, then calls the function again with a smaller input. In countdown, it prints n, then calls countdown(n - 1).

Each call makes n one smaller, so the calls get closer to the base case every time.

Predict: what does countdown.py print?

def countdown(n):
    if n == 0:
        print("Liftoff!")
        return
    print(n)
    countdown(n - 1)

countdown(3)
3
2
1
Liftoff!

4. The call stack: calls wait for each other

Say a folder holds three files of 4, 6, and 2 megabytes (MB, a unit of file size). total_size adds them up with recursion. Its base case is an empty list, which adds up to 0. Its recursive case adds the first size to the total of the rest of the list.

New in this file: sizes[1:] makes a new list with every item except the first. So [4, 6, 2][1:] is [6, 2], and [2][1:] is the empty list [].

Predict: what does total_size.py print?

def total_size(sizes):
    if len(sizes) == 0:
        return 0
    return sizes[0] + total_size(sizes[1:])

print(total_size([4, 6, 2]))
12

How does Python keep track? When total_size([4, 6, 2]) calls total_size([6, 2]), the first call doesn't finish. It pauses and waits for the answer. Python keeps a record of each call: its own sizes value and the line where it paused. That record is a stack frame. All the frames together are the call stack, with the newest call on top. When the base case returns, the paused calls finish one at a time, newest first.

Predict: at the busiest moment, how many total_size calls are on the call stack at once? Count the first call and the base case call.

5. When the base case is never reached

A base case only helps if the calls actually reach it. In countdown_by_two.py, each call takes 2 away from n. Starting at 4, the calls go 4, 2, 0, and stop. Starting at 3, they go 3, 1, −1, −3, and skip right past 0.

Each call that doesn't return adds one more frame to the call stack. If the calls never stop, the stack runs out of room. That's a stack overflow. Python stops the program after about 1,000 frames and raises a RecursionError.

Predict: what happens when countdown_by_two.py runs?

def countdown(n):
    if n == 0:
        return "Liftoff!"
    return countdown(n - 2)

print(countdown(4))
print(countdown(3))
Liftoff!
Traceback (most recent call last):
  File "countdown_by_two.py", line 7, in <module>
    print(countdown(3))

  File "countdown_by_two.py", line 4, in countdown
    return countdown(n - 2)
  File "countdown_by_two.py", line 4, in countdown
    return countdown(n - 2)
  File "countdown_by_two.py", line 4, in countdown
    return countdown(n - 2)

Read the traceback from the bottom up. The last line names the error. The repeated line 4 frames are the same call, stacked hundreds of times.

6. Your turn: count every file

Back to the laptop. In count_files.py, each folder is a dict with two keys: "files", a list of file names, and "folders", a list of the folders inside it. count_files counts the files in one folder, then adds the count from each folder inside it.

There's no if here, but there is still a base case. A folder with no folders inside has an empty "folders" list. The loop runs zero times, so count_files returns without calling itself.

def count_files(folder):
    total = len(folder["files"])
    for sub in folder["folders"]:
        total += ____(sub)
    return total

year_2026 = {"files": ["report.pdf", "budget.txt"], "folders": []}
projects = {"files": ["ideas.txt"], "folders": [year_2026]}
documents = {"files": ["notes.txt", "resume.pdf"], "folders": [projects]}

print(count_files(year_2026))
print(count_files(documents))
2

8. Wrap-up

  • A recursive function calls itself on a smaller piece of the problem.
  • The base case stops the calls. The recursive case moves each call closer to it.
  • Each call waits in its own stack frame. If the base case is never reached, the frames pile up until a RecursionError.

New situation: you add a photos folder with 3 pictures inside Documents. Documents now holds two folders.

Predict: what does the last line of count_photos.py print?

def count_files(folder):
    total = len(folder["files"])
    for sub in folder["folders"]:
        total += count_files(sub)
    return total

year_2026 = {"files": ["report.pdf", "budget.txt"], "folders": []}
projects = {"files": ["ideas.txt"], "folders": [year_2026]}
photos = {"files": ["cat.jpg", "beach.jpg", "party.jpg"], "folders": []}
documents = {"files": ["notes.txt", "resume.pdf"], "folders": [projects, photos]}

print(count_files(photos))
print(count_files(documents))
3
