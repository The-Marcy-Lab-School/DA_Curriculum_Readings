Good validators do not start by trying every possible rule at once. They work from simple structure checks toward more specific content checks.

4. Start with fresh data

These support-ticket records use | as a separator. Each valid line should have exactly three fields: action | ticket_id | priority.

records = [ "OPEN|T104|3", "OPEN|T105|high", "CLOSE|T106", "OPEN|T107|2" ]

Which line clearly has the wrong number of fields?

5. Shape check first

line = "CLOSE|T106" fields = line.split("|") if len(fields) == 3: print("shape OK") else: print("wrong field count")

Why shape first? Later checks may assume a field exists at a specific position. If the shape is wrong, checking a missing field can cause an error.

6. Then check what a field contains

Suppose the shape is correct. The third field should be a whole-number priority.

fields = ["OPEN", "T105", "high"] if not fields[2].isdigit(): print("priority must be numeric")

What happens?

7. Why check order matters

Which order is safer?

A validator should report bad data rather than crash while trying to inspect it. Structure checks protect later, more specific checks.

8. Make error reports actionable with enumerate()

Text editors show the first line as line 1. Python's enumerate() starts at 0 unless you tell it otherwise.

for line_number, line in enumerate(records, start=1): print(line_number, line)

Why use start=1 here?

9. Predict the complete validator

def inspect_records(records): for line_number, line in enumerate(records, start=1): fields = line.split("|") if len(fields) != 3: print(f"Line {line_number}: bad shape") elif not fields[2].isdigit(): print(f"Line {line_number}: bad priority") else: print(f"Line {line_number}: OK")

For "OPEN|T105|high", which branch runs?
