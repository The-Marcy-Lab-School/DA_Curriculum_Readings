2. Validation: is this line usable?

Each line in the office's file should look like "S-2041|10|Biology": a student ID, a grade, and a class, with a | between them. Each part is called a field. A file with one record on each line is a batch file, and a program checks it one line at a time.

Validation means checking data against your rules before you use it. It answers one question: does this input meet our rules? The office has three rules for each line:

  1. The line has exactly 3 fields.
  2. The grade is a whole number.
  3. The grade is from 9 to 12.

A line that passes every rule is valid input. A line that breaks any rule is invalid input. Some invalid lines are also malformed input: they have the wrong shape. "S-2042|Chemistry" has 2 fields instead of 3, so there is no grade to check at all.

To check a line, you first cut it into its fields. .split("|") does that: it cuts a string at every | and gives back a list of the pieces. Each piece is still a string.

What does print(len(short_fields)) print?

Counting the fields is a structure check: it asks whether the line has the right shape. It always runs first. short_fields has no position 2, so reading short_fields[2] would stop the program with an error.

3. Check the grade

Once a line has 3 fields, the grade field still might not be usable. A check on what a field holds is a value check. This file uses four tools for it.

New in this file:

  • grade_text.isdigit() gives True when every character in the string is a digit. "10".isdigit() is True. "10th".isdigit() is False.
  • int(grade_text) turns the text "10" into the number 10, so you can compare it with < and >.
  • not flips True to False and False to True.
  • or is True when either side is True.

The .isdigit() check comes before int() because int("10th") stops the program with an error. Checking first means int() only ever sees digits.

Predict: what does check_grade.py print?

grade_text = "10th"

if not grade_text.isdigit():
    print("Not a number:", grade_text)
elif int(grade_text) < 9 or int(grade_text) > 12:
    print("Outside 9-12:", grade_text)
else:
    print("OK:", grade_text)

4. Decide what the function gives back

Before you write the loop, decide two things: what the function takes in (its input) and what it gives back (its output). Together they are the function's contract. The rest of the program relies on the contract and doesn't need to know how the checks work inside.

INThe list of form lines, exactly as the office typed them.
ONE JOBDecide whether each line is valid, and say why if it isn't.
OUTA list of problem messages. The list is empty if every line is valid.

Why is "return a list of problem messages" the best output for this function?

Each message should name its line, so someone can find the form and fix it. enumerate() gives a loop two things on each pass: a position number and the item. It counts from 0 unless you add start=1.

def find_form_problems(forms):
    problems = []
    for line_number, form in enumerate(forms, start=1):
        fields = form.split("|")

        if len(fields) != 3:
            problems.append(f"Line {line_number}: expected 3 fields, got {len(fields)}")
        elif not fields[1].isdigit():
            problems.append(f"Line {line_number}: grade '{fields[1]}' is not a number")
        elif int(fields[1]) < 9 or int(fields[1]) > 12:
            problems.append(f"Line {line_number}: grade {fields[1]} is outside 9-12")

        return problems

8. Wrap-up

  • Validation checks each line against your rules before anyone uses it.
  • The structure check (count the fields) runs before the value checks (is the grade a number, is it 9 to 12).
  • Decide the contract first. Returning a list of problems lets you test the function on a tiny batch.

New situation: the office's file gets the line "S-2050||Biology". The grade was left blank. "S-2050||Biology".split("|") gives ['S-2050', '', 'Biology']. What does find_form_problems report for this line?

In job interviews, "write a function that checks a batch of records" is a common task, and saying the contract out loud before you code is what interviewers listen for.
