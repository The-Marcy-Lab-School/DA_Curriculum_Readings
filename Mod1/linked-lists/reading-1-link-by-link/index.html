Link by Link

A music app's Up Next queue lists the songs that play after the current one. Picture a queue where each song knows only one thing: which song comes right after it. To reach the fifth song, the app starts at the top and follows those links one song at a time. That chain of links is a linked list.

1. A list without index numbers

Here is the same queue of four songs stored two ways: as a Python list, and as a linked list.

You already know how to store songs in a Python list and reach any one with an index. A list keeps its items side by side, so Python can jump straight to queue[2]. A linked list can't jump. In return, adding a song in the middle changes only two links, while a list has to move every song after it. Interviewers ask about linked lists often, because they test whether you can keep track of what each variable points to.

3. Nodes and pointers

A linked list is built from nodes. A node holds one value, plus a pointer (also called a reference) to the node that comes next. In Python, the pointer is an attribute, usually named next. The last node has nothing after it, so its next is None.

The first node is the head. It is the only way into the list: lose track of it, and you can't reach the other nodes. The last node is the tail. When each node points only forward, to the next node, the list is a singly linked list.

In song_chain.py, the line head.next = second doesn't copy Song B. It points head.next at the same node that second names. That one line is the whole link between the two songs.

Predict: song_chain.py prints four lines. What is the last line, from print(head.next.next.next)?

class Node: def __init__(self, value): self.value = value self.next = None head = Node("Song A") second = Node("Song B") head.next = second third = Node("Song C") second.next = third print(head.value) print(head.next.value) print(head.next.next.value) print(head.next.next.next)

4. Walk the chain

Writing head.next.next.next by hand doesn't work for a queue of 500 songs. Instead, a loop starts at the head and follows next one node at a time. Walking a linked list this way is called traversal.

New in this file: is not None is the opposite of is None. It is True when the variable holds something.

Predict: what does walk_queue.py print?

class Node: def __init__(self, value): self.value = value self.next = None head = Node("Song A") head.next = Node("Song B") head.next.next = Node("Song C") current = head while current is not None: print(current.value) current = current.next
Song A
Song B
Song C

A loop without the None check

The app tries to show the next 4 songs, but the queue holds only 3. show_four.py uses range(4) instead of checking for None:

class Node: def __init__(self, value): self.value = value self.next = None head = Node("Song A") head.next = Node("Song B") head.next.next = Node("Song C") current = head for step in range(4): print(current.value) current = current.next

5. Add a song in the middle

A listener taps Play next on a new song, so it should play right after Song A. In a linked list, two pointers change: the new node points at the song that used to follow Song A, and then Song A points at the new node. The order matters. If Song A's pointer changes first, nothing points at Song B any more, and the rest of the queue is lost.

6. Reverse the queue

A listener taps Reverse queue, so Song C plays first and Song A plays last. Interviewers ask "reverse a linked list" so often that it is a standard warm-up question. The trick is to flip each node's pointer so it points back, without building a new list.

The reverse function walks the chain with three variables: prev is the node just behind, current is the node being flipped, and next_node saves the node ahead before current's pointer changes. One line is missing: the line that flips the pointer.

class Node: def __init__(self, value): self.value = value self.next = None def show(head): current = head while current is not None: print(current.value) current = current.next def reverse(head): prev = None current = head while current is not None: next_node = current.next ____ prev = current current = next_node return prev head = Node("Song A") head.next = Node("Song B") head.next.next = Node("Song C") head = reverse(head) show(head)
Song C
Song B
Song A

  2. The left side is the pointer of the node being flipped: current with a dot and its pointer attribute. The right side is the node it should point back to.

8. Wrap-up

  • A node holds a value and a pointer to the next node. The head is the only way in, and the tail's pointer is None.
  • Traversal follows next from the head and stops when it reaches None.
  • Adding or removing a node changes a pointer or two, while a Python list has to move every item after the change.

New situation: the queue is Song A, Song B, Song C, Song D. The listener removes Song C. Which change takes Song C out of the queue?

In interviews: when you reverse a linked list, say out loud why you save next_node before you flip a pointer, because that reasoning is what interviewers listen for.

Where this goes next: give a node two pointers, one forward and one back, and you get a doubly linked list; give it several "next" pointers, and you get a tree.
