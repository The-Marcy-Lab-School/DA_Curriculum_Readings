Try It, Catch It, Keep Going

A small hotel gets room requests online. A program reads them one line at a time and books each stay. Then one guest types "4 nights" where a plain number belongs. The program stops on that line, and nobody after that guest gets a room. Here you'll learn to catch that one bad line and keep going.

2. One bad line stops everything

Each request line looks like "Okafor|2|double": the guest's name, the number of nights, and the room type. The program splits the line, turns the nights into a number with int(), and books the stay.

Then a request arrives as "Batista|4 nights|single". int("4 nights") can't turn that text into a whole number, so Python raises an exception: an error that stops the program unless code catches it. Python prints a traceback, and every request after Batista's is left without a room.

book_requests.py has no error handling yet. In the line guest, nights_text, room = request.split("|"), the three names on the left each get one field, in order.

Predict: how many "Booked" lines does book_requests.py print before the traceback?

requests = ["Okafor|2|double", "Hale|3|single", "Batista|4 nights|single",
            "Lindqvist|3|double", "Moreau|2|single"]

for request in requests:
    guest, nights_text, room = request.split("|")
    nights = int(nights_text)
    print("Booked", guest, "for", nights, "nights")
Booked Okafor for 2 nights
Booked Hale for 3 nights
Traceback (most recent call last):
  File "book_requests.py", line 6, in <module>
    nights = int(nights_text)
ValueError: invalid literal for int() with base 10: '4 nights'

3. try and except: catch it and keep going

Error handling means deciding, in code, what should happen when an operation fails, so one failure doesn't stop the whole program. In Python you write it with try and except:

  • The try block holds the risky step you want Python to attempt.
  • The except block runs only if a line in try raises the exception named after except. except ValueError: catches a ValueError.
1. TRY

Python runs the lines inside try, top to bottom.

2. DID A LINE RAISE?

No: the rest of try runs, and Python skips except.
Yes: Python leaves try at that line and jumps to the matching except.

3. CONTINUE

Either way, Python then runs the first line after the whole try/except.

Predict: read_nights.py tries two values. What does it print for "4 nights"?

for nights_text in ["3", "4 nights"]:
    try:
        nights = int(nights_text)
        print("Nights:", nights)
    except ValueError:
        print("Could not read:", nights_text)
    print("Done with", nights_text)
Nights: 3
Done with 3
Could not read: 4 nights
Done with 4 nights

What prints for "4 nights"?

Here is the booking program with the conversion inside try. Batista's request is skipped, and Lindqvist and Moreau still get rooms.

requests = ["Okafor|2|double", "Hale|3|single", "Batista|4 nights|single",
            "Lindqvist|3|double", "Moreau|2|single"]

for request in requests:
    guest, nights_text, room = request.split("|")
    try:
        nights = int(nights_text)
        print("Booked", guest, "for", nights, "nights")
    except ValueError:
        print("Skipped", guest, "because nights is not a whole number")
Booked Okafor for 2 nights
Booked Hale for 3 nights
Skipped Batista because nights is not a whole number
Booked Lindqvist for 3 nights
Booked Moreau for 2 nights

4. Name the error you expect

A try block can hold more than one risky step. room_total.py turns the nights into a number and also looks up the room type in a dictionary of nightly prices. Each step can fail in its own way, so each gets its own except block and its own message.

Predict: rates has no "penthouse" key. Which message does room_total.py print?

request = "Lindqvist|3|penthouse"
rates = {"single": 90, "double": 120}

try:
    guest, nights_text, room = request.split("|")
    nights = int(nights_text)
    total = nights * rates[room]
    print(guest, "owes", total)
except ValueError:
    print("Nights is not a whole number for", guest)
except KeyError:
    print("Unknown room type for", guest)
Unknown room type for Lindqvist

Which except block runs?

Four errors come up again and again. Each name tells you what went wrong:

ValueError

int("4 nights"): the right operation, but this value can't be used.

KeyError

rates["penthouse"]: the dictionary has no entry for that key.

IndexError

rooms[5] when rooms has 3 items: the list has no item at that position.

NameError

print(totl) when only total exists: Python can't find that name.

Naming the error matters. A bare except: has no error name after it, so it catches every error, even a NameError from a typo. The program keeps running with a real bug hidden inside it, and nobody sees the traceback that would point to the typo.

6. Wrap-up

  • An exception stops the program at the line that raised it, unless code catches it.
  • try holds the risky step. except runs only when its named error happens. Then Python moves on.
  • Name the error you expect. A bare except: hides real bugs.

New situation: the hotel books stays of 1 to 30 nights. The request "Hale|45|double" arrives. int("45") works and gives 45. What catches this request?

In job interviews, a common follow-up question is "what happens if this value isn't a number?", and a named except is a clear answer. As programs grow, you'll decide for a whole function which errors to catch and which to let show as bugs.
