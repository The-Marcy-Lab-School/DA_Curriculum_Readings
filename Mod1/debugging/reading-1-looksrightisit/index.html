Looks Right. Is It?

Imagine an AI gives you a polished Python script. It runs. No red error. No crash. The output is also wrong. How would you prove it? Today you build a debugging habit for the hardest kind of bug: code that looks believable.

1. Vocabulary: your debugging toolkit

2. Recall: running is not the same as correct

temperature = 8
if temperature >= 8:
    message = "warm"
else:
    message = "cold"

The requirement says only temperatures above 8 are “warm.” The code runs and produces "warm". What kind of problem is this?

3. A repeatable debugging loop

1. PREDICT

What should happen?

2. TRACE

Follow values and branches.

3. CHANGE

Make one evidence-based fix.

4. VERIFY

Rerun, including an edge case.

A good debugger does not begin with random edits. First create a prediction you can compare against reality.

5. Bug hunt #1: the missing last item

scores = [4, 9, 12, 20]
high = 0

for i in range(len(scores) - 1):
    if scores[i] >= 10:
        high += 1

The intention is to inspect all four scores. Which evidence best exposes the bug?

6. Bug hunt #2: data that looks almost identical

tags = ["Urgent", "urgent", "Normal", "URGENT"]
count = 0

for tag in tags:
    if tag == "urgent":
        count += 1

The requirement says capitalization should not matter. What is the strongest fix?

7. Bug hunt #3: boundary values

def has_stock(units):
    return units >= 0

The requirement says “in stock” means at least one unit. Which input is the best edge case for revealing the bug?

Boundary values are bug magnets. When you see >, >=, <, or <=, test the value right on the boundary.

9. Fix one thing, then verify

Tempting approach: notice three suspicious lines, edit all three, then run once.

That can work, but it weakens your evidence. If the output changes, which edit caused it? A more disciplined cycle is: reproduce → isolate → change → rerun.

10. Refactoring is not the same as debugging

Debug

Change incorrect behavior so the program matches its requirement.

Refactor

Change structure while preserving intended behavior—for example, extracting repeated output into a reusable function.

print("Report:", label_a)
print("Total:", count_a)

# ...later...

print("Report:", label_b)
print("Total:", count_b)

11. AI code: fluency is not evidence

Readable names, comments, and confident explanations can make generated code feel trustworthy. But correctness comes from evidence: requirements, tracing, test cases, and verified outputs.
