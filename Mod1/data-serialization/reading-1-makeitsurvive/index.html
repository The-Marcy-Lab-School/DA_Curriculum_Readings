Make It Survive

A school has a weather station on its roof. A Python program keeps each hour's rain in a dictionary. One night the laptop restarts. In the morning, every number is gone, because the numbers only lived inside the running program. To keep data after a program stops, the program must save it to a file.

Your goal: save Python data to a file, load it back, and check what changed on the way. A value can come back looking the same with a different type, and then the program gives wrong answers without any error.

2. Saving means writing text

While the weather program runs, each hour's numbers sit in a dictionary: rain = {6: (0.4, 58), 7: (1.2, 55)}. Each key is an hour of the day. Each value is a tuple: the rain in millimeters (mm), then the temperature in degrees Fahrenheit. One millimeter is about as thick as a dime. When the program stops, every variable it was holding is gone.

A file can only hold text. So to keep the dictionary, the program turns it into text and writes that text to a file. Later, a program reads the text and builds a new dictionary from it.

  • Serialization is turning a Python value into text that can be saved to a file. Its everyday name is saving.
  • Deserialization is building a Python value again from saved text. Its everyday name is loading.
  • A format is the set of rules for how the text is laid out in the file.

This reading uses three formats. Here is one hour's reading saved in each of them:

{"hour": 7, "rain_mm": 1.2}
hour,rain_mm 7,1.2
7:00 rain 1.2 mm

JSON

JSON is a text format for data with structure inside it. A JSON object looks like a Python dict, and a JSON array looks like a Python list.

Use it for: one record that holds a list or another record inside it.

CSV

CSV is a text format for a table. The column names come once, in a header row. Then each line is one row, with commas between the values.

Use it for: a table someone will open in a spreadsheet.

TXT

TXT is plain text with no built-in structure. Your program decides the layout.

Use it for: a simple log that only your own program writes and reads.

3. Open a file, write to it, read it back

This file writes two lines to rain_note.txt, then reads the file back and prints it. Each Run button on this page shows what a file prints when Python runs every line, top to bottom. On your own laptop, you would type python3 write_note.py in the terminal.

New in this file: how with open(...) as f: works

  1. open("rain_note.txt", "w") finds the file, or makes it if it doesn't exist yet. "w" means you plan to write.
  2. as f gives the open file a short name, f, to use in the lines below.
  3. The indented lines run while the file is open. f.write(text) adds that text to the file.
  4. "\n" inside a string means "start a new line here." Without it, the next write lands on the same line.
  5. When the indented lines end, Python closes the file for you. That is why files are opened with with.
  6. f.read() gives back everything in the file as one string.

Predict: what does write_note.py print?

with open("rain_note.txt", "w") as f: f.write("6:00 rain 0.4 mm\n") f.write("7:00 rain 1.2 mm\n") with open("rain_note.txt") as f: text = f.read() print(text)
6:00 rain 0.4 mm
7:00 rain 1.2 mm

The second open() has no mode, so it opens the file for reading. The mode is the second thing you give open(), and it says what you plan to do:

  • "w" (write) empties the file first, then writes. If the file doesn't exist, Python makes it.
  • "a" (append) keeps what is already in the file and adds to the end.
  • No mode, or "r", reads the file.

Every value read from a text file is a string, even text that looks like a number, such as 1.5. Your code has to turn it into a number before doing math with it.

The weather program should add one line to rain_log.txt every hour. The real program runs once an hour. In log_rain.py, each pass of the loop stands in for one of those hourly runs, and the last two lines print what the file holds at the end.

Predict: what does log_rain.py print?

hour_lines = ["6:00 rain 0.4 mm\n", "7:00 rain 1.2 mm\n", "8:00 rain 0.9 mm\n"] # Each pass of the loop stands in for one hourly run. for hour_line in hour_lines: with open("rain_log.txt", "w") as f: f.write(hour_line) with open("rain_log.txt") as f: print(f.read())
8:00 rain 0.9 mm

The fix is one letter: open the log with "a" so each hour adds a line. log_rain_fixed.py writes to a new file, rain_log_fixed.txt, so the line left over in rain_log.txt doesn't get mixed in.

hour_lines = ["6:00 rain 0.4 mm\n", "7:00 rain 1.2 mm\n", "8:00 rain 0.9 mm\n"] # Each pass of the loop stands in for one hourly run. for hour_line in hour_lines: with open("rain_log_fixed.txt", "a") as f: f.write(hour_line) with open("rain_log_fixed.txt") as f: print(f.read())
6:00 rain 0.4 mm
7:00 rain 1.2 mm
8:00 rain 0.9 mm

4. Save and load a dictionary with JSON

Writing a whole dictionary line by line would take a lot of code. Python's json tools do it in one call each:

  • json.dump(value, f) turns value into JSON text and writes it into the open file f. This is serialization.
  • json.load(f) reads the JSON text in f and builds a new Python value from it. This is deserialization.

New in this file: import json

import json loads Python's built-in JSON tools so the file can use them. It goes at the top of the file. After it, json.dump and json.load work.

Each blank in save_and_load.py needs the name of one json function.

import json rain = {6: 0.4, 7: 1.2} with open("rain.json", "w") as f: json.____(rain, f) with open("rain.json") as f: restored = json.____(f) print(restored)
{'6': 0.4, '7': 1.2}
  1. Look at which block each blank sits in. The first blank is inside the "w" block, so it saves. The second is inside the reading block, so it loads.
  2. Type only the function name: no json, no dot, no parentheses. For example, type print, not print().
  3. Press Check both. The feedback says which blank to fix.

Try it: save in one run, load in the next

Real programs split the round trip across two runs. save_rain.py writes the hourly dictionary to rain.json. load_rain.py runs later and builds the dictionary again.

import json rain = {6: (0.4, 58), 7: (1.2, 55)} with open("rain.json", "w") as f: json.dump(rain, f) print("Saved", len(rain), "hours to rain.json")
import json with open("rain.json") as f: rain = json.load(f) print("Loaded:", rain) print("Hour 7:", rain["7"])

len(rain) counts the keys in rain, so it gives 2. Click in the black terminal box, then follow these steps:

  1. Type ls and press Enter. It lists the two files in the folder. There is no rain.json yet.
  2. Type python3 load_rain.py and press Enter. You get an error that ends in FileNotFoundError, because nothing has been saved yet.
  3. Type python3 save_rain.py and press Enter. This writes rain.json.
  4. Type cat rain.json and press Enter. cat shows what is inside a file. Look at the keys and the values.
  5. Type python3 load_rain.py and press Enter again. This time it works. Compare what it prints with the rain dictionary in save_rain.py.

5. What comes back different

The file never holds the dictionary itself. It holds a text version, and loading builds a brand-new dictionary from that text. Two things change on the way, as the diagram shows:

  • JSON keys are always strings, so the integer key 6 comes back as the string "6".
  • JSON has no tuple type, so the tuple (0.4, 58) comes back as the list [0.4, 58].

Nothing crashes when a type changes. The program just gives wrong answers later, so check what type a loaded value really has. For each of the three round-trip files in this section, predict first. The output appears under the file after you answer.

Round 3: a date. What happens when save_date.py runs?

New in this file: from datetime import date loads Python's tool for calendar dates. date(2026, 10, 3) stores October 3, 2026.

import json from datetime import date day_record = {"rain_mm": 1.6, "day": date(2026, 10, 3)} with open("day.json", "w") as f: json.dump(day_record, f)
Traceback (most recent call last):
  File "save_date.py", line 7, in <module>
    json.dump(day_record, f)
    ~~~~~~~~~^^^^^^^^^^^^^^^^
  ...
TypeError: Object of type date is not JSON serializable

The real error also lists a few lines from inside Python's json tools, shortened to ... here. Read your own line (line 7) and the last line, which names the error.

JSON also has three text rules that Python dicts don't follow. They matter when you write or check a JSON file by hand, for example one an AI assistant wrote for you:

  1. Strings and keys use double quotes: "roof", never 'roof'.
  2. true, false and null are lowercase. Python's True, False and None are not valid JSON.
  3. No comma after the last item in an object or array.

7. Wrap-up

  • A file holds a text version of your data, never the live Python value. json.dump saves it and json.load builds a new value from it.
  • Open a file with "w" to start it fresh, "a" to add to the end, and no mode to read it.
  • Check the type of each loaded value. JSON turns integer keys into strings and tuples into lists, and text files give back strings.
