Inside the Inside

A video game has 3 worlds, and each world has 4 checkpoints. The player clears all 4 checkpoints in one world before moving to the next. Some doors ask two questions: do you have a key? If yes, is it the right color? That is a repeat inside a repeat, and a decision inside a decision.

1. The big idea

You already know how to trace one loop and one if. Here you put one inside another. Real data is often built this way: a file has rows, and each row has several values to check. Two rules let you trace all of it:

  1. An inner loop finishes all of its passes before the outer loop moves on by one.
  2. An inner if runs only when Python goes into the outer branch that holds it.

3. A loop inside a loop

A nested loop is a loop written inside the loop body of another loop. (The loop body is the pushed-in code that runs on each pass.) The loop on the outside is the outer loop. The loop inside it is the inner loop.

In checkpoints.py, the outer loop goes through the worlds. On every one of its passes, the inner loop runs all the way through the 4 checkpoints. Each single pass of a loop is one iteration.

Predict: how many lines does checkpoints.py print?

worlds = ["Forest", "Desert", "Ice"]

for world in worlds:

4. Indentation shows what is inside

How far a line is pushed in tells you which loop it belongs to. In practice mode, the game has 2 worlds with 3 checkpoints each. In practice_mode.py, print("play") is pushed in under the inner loop. print(world, "done") is pushed in under the outer loop only, so it runs once per world, after that world's checkpoints.

Predict: how many lines does practice_mode.py print in total?

worlds = ["Forest", "Desert"]

for world in worlds:
    for checkpoint in range(3):

    print(world, "done")

5. An if inside an if

A nested conditional is an if/elif/else written inside one branch of another conditional. The red door asks its questions in order:

Outer question: is the player holding a key?
asked only when the outer answer is True
Inner question: is the key red?

When the outer answer is no, Python never reaches the inner question. It skips it. It does not check it and find it False.

The player is holding nothing. What happens to the "is the key red?" question?

Now put both ideas together. door_check.py loops over what the player holds at three red doors, one item per door. Inside the loop, it asks the two questions.

Predict: what does door_check.py print?

keys_held = ["red", "nothing", "blue"]

for key in keys_held:
    if key != "nothing":
        if key == "red":
            print("door opens")
        else:
            print("wrong key")
    else:
        print("no key")
door opens
no key
wrong key

What prints, one line per door?

On the pass where key is "nothing", does Python check key == "red"?

7. Wrap-up

  • Count a nested loop by multiplying: outer passes times inner passes.
  • Read the indentation first. It tells you which loop or branch a line belongs to.
  • Trace a nested if from the outside in. If Python skips the outer branch, it skips everything inside it.

New situation: each world now has a shop. The game first asks, "Does the player have any coins?" Only if yes does it ask, "Enough coins for a shield?" A player has no coins. Which question does Python check?

In job interviews, "How many lines does this nested loop print?" is a common warm-up question. Say "the inner loop finishes before the outer loop moves on" out loud as you count. Next, the same shape walks a grid one cell at a time and checks several things about every row in a file.
