Inside the Inside

A video game has 3 worlds, and each world has 4 checkpoints. At every checkpoint, the game asks: is the player carrying a key? If yes, it asks a second question: is it the right color? 1. Concept overview

One loop over the 3 worlds does not reach all 12 checkpoints. The player clears checkpoints 1 through 4 of World 1, then 1 through 4 of World 2, then 1 through 4 of World 3.

Code that does this is a nested loop: a loop written inside another loop's loop body, the indented code a loop runs on each pass. The outer loop counts the worlds. The inner loop counts the checkpoints, and it runs all the way through on every pass of the outer loop.

Now add the key. The game asks "is it the right color?" only when the answer to "is the player carrying a key?" is yes. That second question is a nested conditional: a decision written inside one branch of another decision. Python reaches the inner question only when it runs the outer branch that holds it.

Two rules cover every trace in this reading:

  1. An inner loop finishes every one of its iterations before the outer loop advances by one.
  2. An inner conditional runs only when Python enters the outer branch that contains it.

Why this matters: most real data has structure inside structure. A file has rows, and each row holds several values. A sales report has regions, and each region has its own months. "Go through every row, then check a few things about that row" is a loop wrapped around a nested conditional. Tracing code like that out loud is a common warm-up question in technical screens.

Where you're coming from, where this is headed: you already know how to trace a single loop and a single conditional. Here you put one inside another. The same shape scales up: walking a grid cell by cell, checking several fields on every record in a file, and grouping records by category before summarizing each group.

7. Indentation shows what is inside

A tournament script prints one line per round played, then one line when a team's rounds are finished:

for team in range(2): for round_num in range(3): print("play") print("team done")
Need a hint?

Read the indentation before you do any arithmetic. One of the two print calls sits inside the outer loop's body but outside the inner loop's body. That one runs once per outer iteration.

15. How this shows up in interviews

"What does this nested loop print?" is a common warm-up question in technical screens, for data and software engineering roles alike. Interviewers listen to how you trace it, not just the final number. Saying "the inner loop finishes before the outer one moves on" out loud is what they want to hear.

Nested conditionals show up as spot-the-bug questions. You get a few lines where an inner message never prints, and you find the reason live. The expected method is tracing from the outside in, the habit from the order-the-steps activity.

Nested loops are also where the cost of a program starts to multiply. Two loops over the same 10 items run the inner body 100 times. Over 20 items they run it 400 times, so doubling the input makes four times the work. Interviewers often follow a nested-loop trace by asking how the work grows when the input doubles.

Interview-style question: three outer iterations, three inner iterations each, one print per inner iteration. How many lines print in total?
