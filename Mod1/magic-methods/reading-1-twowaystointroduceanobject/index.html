Two Ways to Introduce an Object

A pet-sitting app stores each pet as a Pet object. When you print one, Python shows something like <__main__.Pet object at 0x7f2b1c0a4d90>. That doesn't tell you which pet it is. Two special methods fix this: one describes the pet for people, and one describes it exactly for programmers.

1. One object, two readers

The app texts each owner a message like "Biscuit the dog is booked for Tuesday." A programmer fixing a bug in the app needs something different: the exact values stored on the object. It's the same object with the same data, but two different readers.

The output with the memory address is Python's default representation: the class name plus where the object is stored in the computer's memory. Python shows it when the class doesn't say how to describe itself.

A method whose name starts and ends with two underscores is a magic method, also called a "dunder" method (for "double underscore"). Python calls magic methods for you at the right moment. You already use one: __init__ runs each time an object is made. This reading adds two more, __str__ and __repr__.

3. Add __str__ for people

Here is the Pet class with no description methods yet. Printing a pet shows the default representation. The memory address changes every time you run the file.

class Pet: def __init__(self, name, species): self.name = name self.species = species biscuit = Pet("Biscuit", "dog") print(biscuit)
<__main__.Pet object at 0x7f2b1c0a4d90>

__str__ is a magic method that returns a friendly string for a person to read. When a class has one, print(obj) uses it. Like every method, it takes self, so it can build the string from the object's own attributes. It must return the string, not print it.

Predict: pet_str.py adds a __str__ method. What does it print now?

class Pet: def __init__(self, name, species): self.name = name self.species = species def __str__(self): return f"{self.name} the {self.species}" biscuit = Pet("Biscuit", "dog") print(biscuit)
Biscuit the dog

4. Add __repr__ for programmers

__repr__ is a magic method that returns an exact string for programmers. The usual style looks like the line of code that made the object, such as Pet('Biscuit', 'dog'). Then anyone fixing a bug can see exactly which values the object holds. Calling repr(obj) asks for this string directly.

New in this file: quotes inside an f-string. In f"Pet('{self.name}', '{self.species}')", the double quotes start and end the string. The single quotes inside are ordinary characters, so they print around each value: Pet('Biscuit', 'dog').

Predict: pet_repr.py has both methods and prints two lines. What does it print?

class Pet: def __init__(self, name, species): self.name = name self.species = species def __str__(self): return f"{self.name} the {self.species}" def __repr__(self): return f"Pet('{self.name}', '{self.species}')" biscuit = Pet("Biscuit", "dog") print(biscuit) print(repr(biscuit))
Biscuit the dog
Pet('Biscuit', 'dog')

Your turn: write __repr__

The app also tracks each sitter's visit with a Visit class. Its __str__ is already written. repr(visit) should give Visit('Biscuit', 30): the class name, then the values in the same order as __init__, with quotes around the text value and none around the number.

class Visit: def __init__(self, pet_name, minutes): self.pet_name = pet_name self.minutes = minutes def __str__(self): return f"{self.pet_name}: {self.minutes}-minute visit" def __repr__(self): ____ # write the return line here visit = Visit("Biscuit", 30) print(repr(visit))
Visit('Biscuit', 30)
  1. Type return f" to start returning an f-string.
  2. Type the class name and an opening parenthesis: Visit(
  3. Type the first value with single quotes around it, because it's text: '{self.pet_name}'
  4. Type a comma and a space, then the number with no quotes: {self.minutes}

5. Which one does Python use?

To predict which method runs, ask: what is asking Python to describe the object?

print(obj), str(obj), f"{obj}"

These ask for the friendly view. Python uses __str__. If the class has no __str__, Python uses __repr__ instead.

repr(obj), and every item inside a list

These always use __repr__. A list shows each item it holds with __repr__, even when the item has a __str__.

Predict: pet_list.py prints a list of two pets. The Pet class has both methods. What does it print?

class Pet: def __init__(self, name, species): self.name = name self.species = species def __str__(self): return f"{self.name} the {self.species}" def __repr__(self): return f"Pet('{self.name}', '{self.species}')" pets = [Pet("Biscuit", "dog"), Pet("Mochi", "cat")] print(pets)
[Pet('Biscuit', 'dog'), Pet('Mochi', 'cat')]

7. Wrap-up

  • __str__ returns a friendly string for people. print() uses it.
  • __repr__ returns an exact string for programmers. repr() and lists use it.
  • If a class has no __str__, print() uses __repr__ instead.

New situation: the app adds a Sitter class for the people who visit the pets. It has both methods.

Predict: what does sitters.py print?

class Sitter: def __init__(self, name, visits_today): self.name = name self.visits_today = visits_today def __str__(self): return f"{self.name} ({self.visits_today} visits today)" def __repr__(self): return f"Sitter('{self.name}', {self.visits_today})" sitters = [Sitter("Jordan", 3), Sitter("Sam", 5)] print(sitters)
[Sitter('Jordan', 3), Sitter('Sam', 5)]

"What's the difference between __str__ and __repr__?" is a common interview question. A strong answer names who reads each one and the fallback rule. It also says that if you write only one, write __repr__, because print() falls back to it.

Other magic methods work the same way: for example, __eq__ decides what == means for two of your own objects.
