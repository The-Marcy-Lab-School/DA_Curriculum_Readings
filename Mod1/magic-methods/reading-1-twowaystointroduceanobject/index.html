Two Ways to Introduce an Object

A vet clinic's scheduling script stores each patient as a Pet object. When a developer prints one to debug the script, Python shows something like <__main__.Pet object at 0x7f2b1c0a4d90>. 1. Concept overview

A vet clinic's script tracks every patient with a Pet class that stores the pet's name and species. A developer fixing a scheduling bug prints one pet to check it, and Python shows a memory address. Nothing in that output says which pet it is. The same script also writes reminder texts to owners, and those need a friendly description like "Biscuit the dog." The data is the same both times. The audiences differ: the developer needs something precise, and the owner needs something readable.

Both boxes on the right describe the same object with the same data. What changes is which method Python calls to describe it: __str__ for the friendly view, or __repr__ for the precise one.

Why this matters: many classes you'll meet in real code print as an unreadable default. Two short methods fix that and make debugging faster. "What's the difference between __str__ and __repr__?" is also a common Python interview question.

Where you're coming from, where this is headed: you already write __init__ to store an object's starting attributes. This reading adds two more methods to the same kind of class. Python calls one of them in some situations and the other in others. The same idea, Python calling a special method for you based on context, also decides how objects of your own class are compared and sorted.

4. Which method runs? Context decides

Neither method is better. To predict which one runs, ask: what is asking Python to describe the object?

print(obj), str(obj), and f-strings like f"{obj}"

These ask for the friendly view. Python uses __str__ if the class defines it. If not, Python falls back to __repr__.

repr(obj), and any object shown inside a list, dict, or tuple

These always call __repr__. When a list displays itself, it shows each item's __repr__, even if the item also has a __str__.

5. Practice: predict the default

class Pet: def __init__(self, name, species): self.name = name self.species = species biscuit = Pet("Biscuit", "dog") print(biscuit)

6. Add __str__

class Pet: def __init__(self, name, species): self.name = name self.species = species def __str__(self): return f"{self.name} the {self.species}" biscuit = Pet("Biscuit", "dog") print(biscuit)

What prints now?

7. Add __repr__ too

class Pet: def __init__(self, name, species): self.name = name self.species = species def __str__(self): return f"{self.name} the {self.species}" def __repr__(self): return f"Pet('{self.name}', '{self.species}')" biscuit = Pet("Biscuit", "dog") print(repr(biscuit))

This code calls repr() directly. What prints?

8. Your turn: write __repr__

The clinic's script also tracks appointments with the Appointment class below. Its __str__ is already written. Write the return line for __repr__.

class Appointment: def __init__(self, pet_name, minutes): self.pet_name = pet_name self.minutes = minutes def __str__(self): return f"{self.pet_name}: {self.minutes}-minute visit" def __repr__(self): ____ # write the return statement here visit = Appointment("Biscuit", 30) print(repr(visit))

Target: repr(visit) should produce Appointment('Biscuit', 30). That's the class name, then the values in the same order as __init__, with the string in quotes.

Need a hint?

Look at the __repr__ method in the Pet class. Use the same shape: an f-string that starts with return f"ClassName(, includes both attributes, and puts quotes around the string one.

9. The real gotcha: a list of objects

This is where most people mix up the two methods. A list has to show every item it holds, and it uses each item's __repr__ to do it, even when __str__ exists.

class Pet: def __init__(self, name, species): self.name = name self.species = species def __str__(self): return f"{self.name} the {self.species}" def __repr__(self): return f"Pet('{self.name}', '{self.species}')" pets = [Pet("Biscuit", "dog"), Pet("Mochi", "cat")] print(pets)

The Pet class here has both __str__ and __repr__. What does python3 pet_list.py print?

16. How this shows up in interviews

"What's the difference between __str__ and __repr__?" is one of the most common Python OOP interview questions in data and software roles. A strong answer names who reads each one and states the fallback rule. A definition memorized from a slide is not enough.

Interviewers also listen for a debugging habit. When you check an object in the REPL, a clear __repr__ tells you exactly which object you have. That's why many Python developers write a __repr__ on every class.

The same thing shows up in the log lines and error messages of a large codebase. A clear __repr__ turns an unreadable message into one you can act on.

Interview-style question: if you can only write one of __str__ or __repr__, which should you pick, and why?

19. Thinking ahead

Describing an object two ways is one example of a bigger idea: magic methods let your own class work with Python's built-in tools. __eq__ decides what == means for two of your objects, and __lt__ decides how sorted() orders them. Many libraries you'll use later, such as database tools, expect a clear __repr__ on each class so their logs stay readable.
