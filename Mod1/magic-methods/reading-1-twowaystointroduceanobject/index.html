Two Ways to Introduce an Object

A Python object can have the same data but need two different descriptions: one that is easy for a person to read, and one that is precise enough to help a developer inspect what is happening. Python's __str__ and __repr__ give you those two views.

~17–19 minutesEasy-language diagramsRepeated prediction practiceExtra resources

Keep asking one question: “How is Python being asked to show this object?”

1. Start with a puzzle

Imagine a delivery app has an object named parcel. The object already knows its tracking code and destination. But when a developer prints it, Python shows something like:

<__main__.Parcel object at 0x...>

The data exists. The problem is that Python has not been told how to turn this custom object into a useful description.

Today's idea: magic methods are special method names Python knows to call in certain situations. You write the method; Python chooses when to use it.

Easy-language rule: these methods do not create a second object. They return different strings describing the same object.

5. What each method looks like

class Parcel:
    def __init__(self, code, city):
        self.code = code
        self.city = city

    def __str__(self):
        return f"{self.code} → {self.city}"

    def __repr__(self):
        return f"Parcel('{self.code}', '{self.city}')"

__str__

Think: nice to read.

Called by str(parcel) and normally what print(parcel) displays.

__repr__

Think: useful to inspect.

Called by repr(parcel). It is also the representation you'll see for objects contained inside a list.

7. Diagram: Python's decision path

print(object) / str(object)

Does the class define __str__?

YES → use __str__

No? Python can fall back to the object's __repr__-style representation.

repr(object)

This request is explicit.

→ use __repr__

No guessing: you asked for the representation.

The key is not “Which method is better?” The key is what context is asking Python to represent the object?

9. The tricky part: an object inside a list

This is where many learners mix the two methods up. A list needs a representation for each item it contains, so it uses each item's __repr__.

16. Required bridge to lecture/lab

You just learned that __str__ and __repr__ are two string views of the same object, and that Python chooses between them based on context. In lecture/lab, you will extend a class you already know by adding these methods and then test which one Python actually uses.

Be ready to recognize this decision habit: first identify the context—direct print, explicit repr, or object inside a collection—then predict the representation.
