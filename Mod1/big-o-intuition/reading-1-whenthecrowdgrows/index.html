When the Crowd Grows

At the airport, a check-in screen finds your booking from a six-letter code. With 200 bookings, any search feels instant. With 200,000, the way the screen searches decides whether you wait one second or much longer. Big-O is the language for that difference.

1. Introduction

You type the booking code from your ticket, and the screen has to find your booking among all the others. You already write loops that check items one at a time. This reading shows what that habit costs as the list of bookings grows. Interviewers ask about this often, and it guides how you store data at work.

3. Idea 1: a linear search checks one item at a time

Here is one way the check-in screen can find a booking. It looks at the first booking, then the second, then the third, until one matches. A step-by-step method like this is an algorithm: a list of steps that solves a problem. This one is called a linear search, also called a linear scan, because it moves along the list in a line.

Python has a short way to write a linear search: the word in.

New in this file: "QX7RT2" in bookings gives True if the list holds "QX7RT2", and False if it doesn't. Behind the scenes, in runs the same loop as has_booking: it checks the list from the start, one item at a time.

4. Idea 2: the worst case grows with the input size

How much work does a linear search do? It depends on where the booking sits. If it is first, the search checks 1 booking. The worst case is the situation that takes the most work: the booking is last, or it is not there at all. Then the search checks every booking.

The number of items is the input size. Big-O calls it n. Python's len() gives it to you.

New in this file: len(small) gives how many items the list small holds. The function count_checks is has_booking with a counter added: checks += 1 runs once for every booking it looks at, and the function returns that count.

Predict: what does the last line of count_checks.py print?

def count_checks(code, bookings): checks = 0 for entry in bookings: checks += 1 if entry == code: return checks return checks small = ["LM2B8K", "RT9PW4", "BB4HN1", "QX7RT2"] big = ["LM2B8K", "RT9PW4", "BB4HN1", "QX7RT2", "HJ3KD9", "PL8MN2", "WE5RT7", "CV1BN6"] print(len(small), count_checks("LM2B8K", small)) print(len(small), count_checks("ZZ1AA1", small)) print(len(big), count_checks("ZZ1AA1", big))

The list big holds 8 bookings, and "ZZ1AA1" is not in it. What does the last line print?

Look at the last two lines of output. The list doubled from 4 to 8 bookings, and the worst case doubled from 4 checks to 8. Big-O is a way to describe how an algorithm's work grows as its input size grows. A linear search is O(n), said "O of n": in the worst case, it checks all n items, so its work grows with n.

A linear search checks up to 300 bookings in the worst case. Then the list doubles to 600 bookings. What is the new worst case?

5. Idea 3: a lookup jumps straight to the item

Think of a coat check. You hand over your coat and get ticket 42. Later, the worker walks straight to hook 42. Nobody checks hooks 1 to 41 first. Finding one item this way is a lookup: you go straight to the item by its number or label.

A Python list works like this for positions. Each item has a position number, called an index, and Python jumps straight to it.

New in this file: bookings[0] gives the item at position 0. Python counts positions from 0, so bookings[0] is the first item and bookings[3] is the fourth.

Predict: what does print(bookings[3]) show?

bookings = ["LM2B8K", "RT9PW4", "BB4HN1", "QX7RT2"] print(bookings[0]) print(bookings[3]) print(len(bookings))
LM2B8K
QX7RT2
4

A lookup does about the same work with 4 bookings or 200,000. Big-O calls that O(1), said "O of 1": the work stays about the same as the input grows. The check-in screen doesn't know your booking's position, though. It knows your code. Python has a container that files each item under a label, like a coat-check ticket, so finding a booking by its code is also O(1). You will meet that container soon.

How an algorithm behaves as its input grows is called its scale. Code that stays fast as the data grows "scales well." Pick a size below. Each choice doubles the bookings, and the bars are drawn to scale.

O(n)

Linear search, worst-case checks: 25,000

O(1)

Lookup by code: about 1 step

Careful: O(1) does not mean zero time, and O(n) does not mean slow. A linear search over 5 items finishes almost at once. Both labels describe how the work grows, not how many seconds one run takes.

7. Wrap-up

  • A linear search checks items one at a time. Its worst case is the item being last or not there at all.
  • The input size, n, is how many items there are. A linear search is O(n): double the items, double the worst case.
  • A lookup jumps straight to the item by its position or label. It is O(1): the work stays about the same as the data grows.

New situation: at the gate, a scanner checks each boarding pass against the flight's list of passengers, using in on a list. The airline switches from 100-seat planes to 400-seat planes.

What happens to the scanner's worst case?

In interviews, you may hear "What is the Big-O of this search, and why?" A good answer names n, describes the worst case, and says whether the work grows or stays flat.

When one loop runs inside another, the work grows even faster than O(n), and that pattern has its own Big-O name.
