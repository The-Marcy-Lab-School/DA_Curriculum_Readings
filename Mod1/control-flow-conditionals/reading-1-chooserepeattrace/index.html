Choose, Repeat, Trace

A movie theater's scheduling script reads tonight's movies one at a time. For each movie it asks one question: is this movie longer than 150 minutes? If yes, the script books a long time slot. If no, it books a standard slot. Then it asks the same question about the next movie, until the list runs out. Picking the slot is a conditional. Asking again for every movie is a loop.

1. Concept overview

Start with one movie that runs 98 minutes. The script asks: is 98 more than 150? No, so it books a standard slot and skips the long-slot path. Code shaped like this is a conditional: it checks a condition and picks which branch runs.

One movie is never the whole schedule. The script asks the same question about every movie on the list, in order, until none are left. That repeating is a loop. One pass through it, one movie and one answer, is an iteration. The code that runs on each pass is the loop body. Here, the loop body checks the runtime and books a slot.

Why this matters: a loop that visits every item, plus a conditional that decides what to do with each item, is the shape behind most code that handles a list. Filtering records, flagging bad rows, and pulling out the rows someone needs to see all use it. Interviewers often open with six lines of it and ask what it prints.

Where you're coming from, where this is headed: you already know how to compare two values and how to store a list of them. This reading adds two controls: what happens to each item, and how many times code repeats. After that comes putting one loop inside another, and then wrapping the whole pattern in a reusable piece of code you can point at any list.

Python runs the same steps in the same order every time. So if you read the code carefully, you can say exactly what it prints before you run it. That is the skill this reading builds.

4. if / elif / else: exactly one path runs

Python reads an if/elif/else chain from top to bottom and stops at the first branch whose condition is True. An elif is checked only when every earlier branch in the chain was False. An else runs only when no earlier branch was True. So exactly one branch runs, and tracing the chain means finding that branch. A chain with no else can run no branch at all, when every condition is False.

The theater's lobby screen tells moviegoers how soon their show starts. In lobby_screen.py, the show starts in 25 minutes. Predict what prints before you run it.

7. Off-by-one errors: wrong by exactly one


The theater has seven screens. Before the doors open, screen_check.py should print one line for each screen:


for screen in range(6):
    print("checking screen", screen + 1)


Running python3 screen_check.py prints this:


checking screen 1
checking screen 2
checking screen 3
checking screen 4
checking screen 5
checking screen 6


Six lines, not seven. range(6) gives 0 through 5, so screen + 1 stops at 6. Screen 7 never gets checked. This is an off-by-one error: a loop that runs one time too many or one time too few, because its start or stop value is one step off.


Python raises no error here. screen_check.py runs and finishes normally, so nothing on screen says anything is wrong. Two habits catch it:


    
  
  1. Trace the first and last iterations by hand, and compare them with what you meant. The first should be screen 1, and the last should be screen 7.
    2. 
  
  2. Count the lines that print, and compare that count with the number you expected. Six is not seven.

12. Two ideas, one move: loop + conditional together


A loop visits every item. A conditional inside the loop body decides what happens to the current item, and Python checks that condition again on every iteration. This is the runtimes loop from the theater's scheduling script, runtimes.py:


runtimes = [98, 165, 150]

for runtime in runtimes:
    if runtime > 150:
        print(runtime, "long slot")
    else:
        print(runtime, "standard slot")

15. How this shows up in interviews




"Trace this code and tell me what prints" is one of the most common opening questions in data and software engineering interviews. Interviewers listen to how you reason: reading top to bottom, naming the branch that runs, and saying what each iteration does. The reasoning counts as much as the final answer.


An off-by-one error is a common follow-up. You get a loop that runs one time too few or too many, and you say out loud which boundary is wrong, without running it.


For data roles, a loop that visits every row, with a conditional deciding what to do with each row, is the idea behind most "clean this column" or "filter these records" questions. You use it before you ever use a library built for that work.




Interview-style: a loop iterates over 6 items. Inside, a conditional only prints when an item is over 50. Exactly 2 of the 6 items are over 50. How many lines print in total?
