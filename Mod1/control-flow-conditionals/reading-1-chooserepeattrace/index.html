Choose, Repeat, Trace

A personal budgeting app reviews yesterday's transactions, one at a time. For each one it asks the same question: is this over $75? The answer changes what happens next: flag it for review, label it routine, or something else entirely. The app doesn't treat every transaction the same way, and it doesn't check just once. It repeats the same question for every transaction on the list until the list runs out. That combination, a conditional that chooses a path, and a loop that controls what repeats, is what this reading is about.

1. Concept overview

Picture the budgeting app from the intro. It has a list of transactions from yesterday, and it walks through them one after another. For each single transaction, it asks: is the amount over $75? If yes, it flags the transaction for review. Otherwise, it just files it as "routine." That's a conditional — code that checks a condition and runs exactly one matching branch, never more than one.

Now notice what happens across the whole list: the app doesn't ask that question once. It asks it once for every single transaction, in order, until there are no transactions left. That repeating behavior is a loop. Each single pass through the list — one transaction, one question, one answer — is an iteration. And the actual instructions that run during each pass, the part that checks the amount and decides what to print or store, is the loop body.

Why this matters: a loop that visits every item plus a conditional that decides what to do with it is the shape behind almost every real program that processes a list of things — filtering transactions, flagging records, sorting search results. It's also one of the very first things an interviewer asks you to trace out loud, before anything more advanced.

Where you're coming from, where this is headed: you already know how to compare two values and store a list of things. This reading is about controlling what happens to each item and how many times something repeats. Once tracing a single loop and a single conditional feels automatic, the next step is putting loops and conditionals inside each other, and eventually wrapping this whole pattern inside a function you can reuse on any list.

Put those two ideas together and you have the shape behind almost every real program that processes a list of things: a loop that visits every item, and a conditional that decides what to do with the one it's currently looking at. The rest of this reading is about getting fast and accurate at predicting exactly what a short snippet like that will do, before you ever run it.

4. if / elif / else: exactly one path runs

Python checks branches from top to bottom and stops at the first one that's True. An elif only gets checked if every branch above it was False, and else only runs if nothing above it matched.

A budgeting app sees amount = 42. What prints?

if amount > 100: print("flag") elif amount > 50: print("review") else: print("routine")

15. How this shows up in interviews

"Trace this code and tell me what prints" is one of the most common opening questions in both data and software engineering interviews. Interviewers are listening for how you reason through it — reading top to bottom, catching the exact branch that runs — not just whether you land on the right final answer.

Off-by-one mistakes with range() and while-loop boundaries are a classic follow-up: you're handed a snippet that's one iteration too short or too long and asked to find exactly where, live.

For data roles specifically, this shape — a loop visiting every row, a conditional deciding what to do with each one — is the mental model behind almost every "clean this messy column" or "filter these records" prompt, long before you ever touch a library built for it.

Interview-style: a loop iterates over 6 items. Inside, a conditional only prints when an item is over 50. Exactly 2 of the 6 items are over 50. How many lines print in total?

16. Summary & critical thinking

Two habits carried this whole reading: reading an if/elif/else chain top to bottom to find the one branch that actually runs, and tracking a loop's iterations one pass at a time instead of guessing the total.
