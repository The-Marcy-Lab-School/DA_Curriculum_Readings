Meet the Objects

A budgeting app lets you save for several goals at once, like a Bike Fund and a Trip Fund. Each goal has a name, how much you want to save, and how much you've saved so far. One goal's numbers must never mix with another goal's. Python's tool for keeping them apart is a class.

Skills you'll practice in this reading:

Object-Oriented Programming — Designing a class with the right attributes and methods for a real problem, and explaining how its objects behave independently of each other.

1. One goal is easy. Two goals get messy.

One goal fits in three variables: name, target_amount, and saved_amount. Now add a second goal. You either write over the first goal's variables, or you make name_2, target_2, and saved_2 and hope you never mix them up. With ten goals, that plan falls apart.

A class describes one kind of thing, once. Here, the class says that every savings goal has a name, a target amount, and a saved amount. From that one class, Python can make as many objects as you need. An object is one goal built from the class, holding its own values. Another word for object is instance: goal_a is an instance of the SavingsGoal class.

Writing programs around objects like these, where each object holds its own data and its own actions, is called object-oriented programming (OOP). You already group values under labels with a dict. A class does that too, and it also holds the actions that work on those values. "Design a class for this problem" is a common interview question, and this reading gives you the parts you need to answer it.

3. Build a class with __init__

Here is the SavingsGoal class, with one goal made from it. Each part has a job:

  • class SavingsGoal: starts the class. Everything indented under it belongs to the class. Class names start with a capital letter.
  • __init__ (say "dunder init," for the double underscores) is a function inside the class that Python runs by itself, once, each time you make a new object. Its job is to store the new object's starting values.
  • self is the object being set up. In self.name = name, the right side is the value that came in through the parameter name. The left side stores that value on this object, under the label name.
  • A value stored on an object, like goal_a.name, is an attribute. You read it with a dot: the object, a dot, then the attribute's name.

When the line goal_a = SavingsGoal("Bike Fund", 500, 420) runs, Python does four steps:

  1. Python makes a new, empty SavingsGoal object.
  2. Python calls __init__ and passes that new object in as self. You never pass self yourself.
  3. The arguments fill the other parameters in order: "Bike Fund" goes into name, 500 into target_amount, and 420 into saved_amount. Each line in __init__ stores one of them on the object.
  4. Python stores the finished object in the variable goal_a.

Running a file means Python does every line, top to bottom. The Run button shows what it prints. On your own laptop you'd type python3 savings_goal.py in the terminal.

In budget_category.py, the two lines inside __init__ that store those values are missing. Without them, the values passed in are lost when __init__ ends, and groceries.label fails.

5. Methods and self

A method is a function written inside a class. It works on one object's own data. The is_funded method below checks whether a goal has reached its target. Its only parameter is self, so it can read that object's attributes.

You call a method with a dot and parentheses: goal_a.is_funded(). The parentheses mean "run this method." Without parentheses, goal_a.saved_amount just reads an attribute. When a method runs, Python sets self to the object before the dot.

Predict: what does two_goals.py print?

class SavingsGoal: def __init__(self, name, target_amount, saved_amount): self.name = name self.target_amount = target_amount self.saved_amount = saved_amount def is_funded(self): return self.saved_amount >= self.target_amount goal_a = SavingsGoal("Bike Fund", 500, 420) goal_b = SavingsGoal("Trip Fund", 1200, 1200) print(goal_a.is_funded()) print(goal_b.is_funded())
False
True

6. Each object keeps its own values

Two objects can come from the same class, but each one stores its own attributes. Changing one object's attribute leaves every other object alone. Reading an attribute later doesn't run __init__ again, either. __init__ ran once, when the object was made.

Predict: goal_change.py changes only goal_a. What number prints after goal_b:?

class SavingsGoal: def __init__(self, name, target_amount, saved_amount): self.name = name self.target_amount = target_amount self.saved_amount = saved_amount def is_funded(self): return self.saved_amount >= self.target_amount goal_a = SavingsGoal("Bike Fund", 500, 420) goal_b = SavingsGoal("Trip Fund", 1200, 1200) goal_a.saved_amount = 480 print("goal_a:", goal_a.saved_amount) print("goal_b:", goal_b.saved_amount)

8. Wrap-up

  • A class describes one kind of object, once. Each object made from it is an instance with its own attribute values.
  • __init__ runs once for each new object and stores the starting values on self.
  • A method is a function inside the class. When it runs, self is the object before the dot.

New situation: the app adds an add_money method. It updates an attribute the same way you update a variable: the new value is the old value plus amount.

Predict: what does add_money.py print?

class SavingsGoal: def __init__(self, name, target_amount, saved_amount): self.name = name self.target_amount = target_amount self.saved_amount = saved_amount def is_funded(self): return self.saved_amount >= self.target_amount def add_money(self, amount): self.saved_amount = self.saved_amount + amount goal_a = SavingsGoal("Bike Fund", 500, 420) goal_c = SavingsGoal("Phone Fund", 300, 0) goal_a.add_money(80) print(goal_a.name, goal_a.saved_amount, goal_a.is_funded()) print(goal_c.name, goal_c.saved_amount, goal_c.is_funded())
Bike Fund 500 True
Phone Fund 0 False
