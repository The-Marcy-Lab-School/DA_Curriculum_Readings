Meet the Objects

A budgeting app lets one person track several savings goals at once: an emergency fund, a vacation fund, a new laptop. Every goal has a name, a target amount, and the amount saved so far. Each goal's numbers must stay separate from every other goal's numbers. Python's tool for this is a class. You describe a savings goal once, then create as many separate goals from that description as you need.

1. Concept overview

A user sets up a goal called "Emergency Fund," with a target of $5,000 and $4,200 saved. Three variables can hold that goal: name, target_amount, and saved_amount. Then the same user adds a second goal, "Vacation Fund." Now you either overwrite the first goal's variables, or you invent name_2, target_2, and saved_2 and hope you never mix them up. With many users and many goals each, that plan falls apart.

A class describes a savings goal once. Every goal has a name, a target amount, and a saved amount, and every goal can report whether it's fully funded. From that one class, Python creates as many objects as you need. Each object stores its own values for those three pieces of data.

Writing programs this way, around objects that carry their own data and their own actions, is called object-oriented programming (OOP).

The class is the same for goal_a and goal_b. Each object stores its own name, target_amount, and saved_amount. If you change one object's saved amount, the other object keeps its own.

Why this matters: "Design a class for X" is a common early interview and take-home prompt in data and software roles. A class also prevents a common bug. When you track similar records in separate variables, or in separate lists that you keep in sync by hand, one record's number can end up next to another record's name. Python raises no error when that happens, so the wrong number reaches whoever reads the report.

Where you're coming from, where this is headed: you already write functions that take parameters, and you use a dict to group values under labeled keys. A class combines both ideas. Its __init__ method stores values under labeled names, the way a dict does, and the class also holds the methods that act on that data. The same class shape later lets an object describe itself when it's printed, and lets you compare ways to find one object among thousands.

4. Read the shape of a class

class SavingsGoal: def __init__(self, name, target_amount, saved_amount): self.name = name self.target_amount = target_amount self.saved_amount = saved_amount def is_funded(self): return self.saved_amount >= self.target_amount goal_a = SavingsGoal("Emergency Fund", 5000, 4200)

Trace the creation call: arguments fill the parameters in order, after self. So "Emergency Fund" goes into name, and self.name = name stores it on the new object. 5000 and 4200 go into target_amount and saved_amount the same way.

What is the value of goal_a.name?

14. How this shows up in interviews

"Design a class for X" is a common early interview and take-home prompt in data and software roles. X might be a parking ticket, a hotel reservation, or a shipment. Interviewers listen for two things. First, can you tie each attribute to something the task actually asked for? Second, can you prove, not just claim, that two objects don't affect each other?

The same decisions come up outside interviews. Any codebase that represents a real thing as a class, such as a user, an order, or a device, needed someone to choose its attributes and methods.

Interview-style question: you've designed a class for a single parking ticket. Which test best proves that two Ticket objects store their fines separately?

15. Debugging habit and reflection

Before this app used a class, a teammate kept goal names in one list and saved amounts in a second list. The two lists were matched by position. The user then deleted "Laptop Fund," and the code removed it from names only.

names = ["Emergency Fund", "Laptop Fund", "Vacation Fund"] saved = [4200, 650, 1200] names.remove("Laptop Fund") for i in range(len(names)): print(names[i], saved[i])

What amount does this loop print next to Vacation Fund?

A SavingsGoal object prevents this bug. A goal's name and saved amount live on the same object, so deleting the goal removes both at once.

16. Summary and critical thinking

A class describes one kind of object, once. __init__ stores each new object's values as that object's own attributes, separate from every other object's attributes.
