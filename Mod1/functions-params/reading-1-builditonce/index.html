Build It Once, Use It Again

A laundromat is a shop where people pay to use washing machines. Every bill uses the same math: the number of loads times the price per load. You could retype that math for every customer. Or you could write it once, give it a name, and reuse it. That named, reusable piece of code is a function.

1. The same math in many places

Washing one load costs $3.50. (A load is one machine full of clothes.) Today, one customer washed 2 loads, another washed 5, and a third washed 3. Without a function, the laundromat's program repeats the same two lines for each customer. Only the number changes.

Copied math causes bugs. Say the price goes up to $4.00. Someone has to find and change every copy. If they miss one, that copy keeps charging the old price. A function keeps the math in one place, so there is only one place to change it.

You already know how to store values, write loops and if statements, and print results. In this reading, you give a set of steps a name and reuse it with different inputs.

How the examples work: each example is a .py file. Running a file means Python does every line, top to bottom. The Run button shows what it prints. On your own laptop, you'd type python3 name.py in the terminal.

3. Define it once, call it many times

A function is a named, reusable block of code. You define it with a def line, which gives the function its name and lists its inputs. The indented lines under the def line are the function's body. To call a function, write its name followed by parentheses. Only a call runs the body.

Here is the laundromat's math as a function named wash_cost, called two times:

def wash_cost(loads, price_per_load): return loads * price_per_load print(wash_cost(2, 3.5)) print(wash_cost(5, 3.5))
7.0
17.5

The body of wash_cost ran two times, once for each call. Each call printed a different answer because each call passed in a different number of loads. (The answers end in .0 or .5 because multiplying by a decimal like 3.5 gives a decimal.)

Predict: what does closing_notice.py print?

def show_closing_notice(): print("Closing early Sunday at 6 p.m.") # No call appears in this file.
(no output)

To make the notice appear, add a call as the last line of the file:

def show_closing_notice(): print("Closing early Sunday at 6 p.m.") show_closing_notice()
Closing early Sunday at 6 p.m.

4. Parameters, arguments, and the return value

A parameter is a name in the def line. It holds a spot for an input. An argument is the real value passed in at a call. It fills the matching parameter. In the call wash_cost(2, 3.5), the argument 2 fills loads and 3.5 fills price_per_load.

Each washer has a label on it. machine_label.py builds that label:

New in this file: + between two strings joins them into one string. "WASHER " + "W-12" becomes "WASHER W-12". The space inside "WASHER " keeps the two words apart.

def machine_label(machine_id): return "WASHER " + machine_id label = machine_label("W-12") print(label)
WASHER W-12

The return line hands an answer back to the line that called the function. That answer is the return value. The calling line can store it in a variable, add it to a total, or print it. In machine_label.py, the return value "WASHER W-12" was stored in label.

5. return hands it back; print only shows it

print shows a value on the screen for a person to read. return hands a value back to the code. A function with no return line hands back None, which is Python's word for "no value."

New in this file: str() turns a number into text, so str(7.0) gives "7.0". You need it in show_cost.py because + can only join text to text.

Predict: show_cost.py prints two lines. What does the second line, from print(saved), show?

def show_cost(loads, price_per_load): print("This visit costs $" + str(loads * price_per_load)) saved = show_cost(2, 3.5) print(saved)
This visit costs $7.0
None

The fix is to return the cost and let the calling line decide what to do with it. return_cost.py returns the cost, stores it, then prints a message.

New in this file: an f-string. Put f just before the opening quote, and Python fills each {name} with that variable's value. f"This visit costs ${saved}" becomes This visit costs $7.0. It does the same job as + and str() with less typing.

def wash_cost(loads, price_per_load): return loads * price_per_load saved = wash_cost(2, 3.5) print(f"This visit costs ${saved}")
This visit costs $7.0

A return in the wrong place

A return line also ends the function right away. total_loads should add up the loads washed on three days: 12, 9, and 15, which make 36.

New in this file: total += loads is a short way to write total = total + loads.

def total_loads(daily_loads): total = 0 for loads in daily_loads: total += loads return total print(total_loads([12, 9, 15]))
12

The program prints 12, not 36, and shows no error. What is wrong?

In week_loads_fixed.py, the return line moves out of the loop, so it runs once, after all three days are added:

def total_loads(daily_loads): total = 0 for loads in daily_loads: total += loads return total print(total_loads([12, 9, 15]))
36

7. Wrap-up

  • You define a function once with def, and only a call runs its body.
  • Parameters let each call pass in different arguments without changing the function's code.
  • return hands a value back to the calling line; print only shows it on the screen.

New situation: the laundromat also rents dryers. Each dryer total is minutes used times the price per minute, and every total gets added to the day's sales. Which design fits?

In interviews: when people see the same lines repeated, they often ask you to turn them into a function that returns its answer instead of only printing it.
