Same Rows, Two Shapes

An animal rescue keeps every adoption as one row in a database table. The people who run it want to know how many Riverton families adopted each kind of animal. You already know how to answer that in SQL and in pandas. Both ways give the same numbers, but they do the work on different computers.

1. One set of rows, two containers

Second Chance Paws is a small animal rescue. It keeps its records in a database, a program that stores an organization's data and answers questions about it. You ask a database questions in SQL. Each adoption is one row in a table called adoptions.

Both boxes hold the same rows and columns. The top box lives on a server, a computer that stays on all the time and holds the data for everyone. The bottom box is a DataFrame: a pandas table held in memory, your computer's fast, temporary workspace. When the program stops, whatever was in memory is gone. Analysts use SQL and pandas side by side every day, so knowing which job belongs where saves real time.

2. Recall before you start

Grouping and counting in SQL and pulling one column out of a pandas table are prerequisite skills for this reading. Check both before moving on.

What does this query give you back?

SELECT species, COUNT(*) FROM adoptions GROUP BY species;

In pandas, adoptions is a table of data. What does adoptions["species"] give you?

3. Same parts, two vocabularies

A query is a request written in SQL, and the rows it sends back are the query result. In Python, pandas keeps every part of that result and renames some of them. One column on its own, like adoptions["species"], is a Series. The type pandas gives a column is its dtype, short for data type.

New in this file: pd.DataFrame({...}) builds a DataFrame from a dict. Each key is a column name, and each list holds that column's values. .dtypes lists every column with its dtype.

animal_id         int64
species          object
adoption_fee    float64
dtype: object

Which dtype prints for adoption_fee?

A whole-number column is INTEGER in the database and int64 in pandas. A text column is TEXT in the database, and pandas prints object.

4. The rescue's question, written twice

How many Riverton adoptions were there for each species? In SQL, one query does the whole job, on the database's computer.

SELECT species, COUNT(*) AS adoptions FROM adoptions WHERE adopter_town = 'Riverton' GROUP BY species;

In pandas, two lines do the same jobs. riverton_count.py types in the same six adoptions, this time with each adopter's town.

Predict: what count does riverton_count.py print next to Dog?

import pandas as pd adoptions = pd.DataFrame({ "animal_id": [1041, 1042, 1043, 1044, 1045, 1046], "species": ["Dog", "Cat", "Dog", "Rabbit", "Cat", "Dog"], "adopter_town": ["Riverton", "Glenway", "Riverton", "Ashton", "Riverton", "Glenway"], }) riverton = adoptions[adoptions["adopter_town"] == "Riverton"] print(riverton["species"].value_counts())
species
Dog    2
Cat    1
Name: count, dtype: int64

What count prints next to Dog?

The SQL query sends back the same counts that riverton_count.py prints. Here is how the pieces line up:

  • WHERE adopter_town = 'Riverton' becomes adoptions["adopter_town"] == "Riverton", which keeps the matching rows.
  • SELECT species becomes riverton["species"], a Series.
  • GROUP BY species plus COUNT(*) becomes .value_counts(), which counts each value in the column.

5. Where the rows live, and where the work happens

A DataFrame is a copy of the rows. If you drop a row or fix a misspelled town in the DataFrame, you changed your copy and nothing else. The database still has its originals.

You load the adoption rows into a DataFrame and fix three misspelled town names there. A teammate then asks the database for the same rows. What does the teammate see?

Where the rows live also decides which computer does the work. The rescue shares its database with other shelters, so the real adoptions table has 4,000,000 rows.

Both options give the right answer. Option 2 sends 4,000,000 rows across the network into your computer's memory, just so pandas can throw most of them away. The database is built to count rows where they sit.

You need the per-species counts for one town from the 4,000,000-row table. Which plan should you use first?

6. The tool that installs pandas: uv

pandas is a package: code someone else wrote that you install and then import. uv is a fast tool that installs a project's packages and keeps them separate from your other projects, instead of running pip directly. It also writes a lock file listing the exact version of every package. Without that list, code that runs for you can crash for a teammate who installed a newer version.

8. Wrap-up

  • A database table and a DataFrame hold the same parts: rows, named columns, and one type per column. pandas calls a column a Series and its type a dtype.
  • The table lives on a server. The DataFrame is a copy in your computer's memory, and changing it never changes the database.
  • Shrink the data in SQL first, then work with the small result in pandas.

New situation: the rescue's leaders want a chart of the average number of days from arrival to adoption for each species in 2025. The shared table has 4,000,000 rows and about 10 species. Which plan is the better first move?

In interviews, "should this happen in SQL or in pandas?" is a common question, and a strong answer starts by asking how big the table is.
