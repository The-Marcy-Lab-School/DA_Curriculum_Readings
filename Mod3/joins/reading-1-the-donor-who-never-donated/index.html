The Donor Who Never Donated

Bright Path Literacy is a small charity that teaches adults to read. It keeps one table of supporters and another of donations. Jo signed up but hasn't given yet. Ask both tables one question, and Jo either disappears or stays with a blank. One word in your query decides which: INNER or LEFT.

3. INNER JOIN keeps the matches

A join combines rows from two tables into one result. The join condition is the ON part. It says which columns must be equal for two rows to go together. Here, s.id = d.supporter_id pairs each gift with the supporter who gave it. A row that finds a partner this way is a matched row.

INNER JOIN keeps only matched rows. A plain JOIN means the same thing.

New in this file: supporters AS s gives the table a short nickname, s. Then s.name means "the name column from supporters." ORDER BY s.id, d.donation_id sorts by supporter first, then by gift number when one supporter has two rows.

 Marcus |     40
(3 rows)

Marcus shows up twice because Marcus gave twice. A join makes one row for each match, so one person can fill many rows. Jo is missing, because no gift matches Jo's id of 103.

4. LEFT JOIN keeps everyone on the left

The left table is the one named right after FROM, before the word JOIN. LEFT JOIN keeps every row of the left table, matched or not. When a left row has no match, the columns from the other table get NULL, which is SQL's word for "no value here." NULL is not zero and not an empty word.

Predict: left_join.sql changes one word. How many rows does it print?

  name  | amount
--------+--------
 Priya  |     50
 Marcus |     75
 Marcus |     40
 Jo     |
(4 rows)

Jo is back, with NULL in the amount column. (psql leaves a NULL spot blank instead of printing the word.)

Bright Path now has 500 supporters. The LEFT JOIN version returns 500 rows, and the INNER JOIN version returns 320. What is the most likely reason?

5. Find the supporters who haven't given

To call the people who haven't given, keep only the LEFT JOIN rows where the amount is NULL. Here is a first try.

Predict: what does equals_null.sql print?

 name | amount
------+--------
(0 rows)

SQL never counts NULL as equal to anything, not even another NULL, so = NULL is never true. It gives no error, just no rows. The rule: test for a missing value with IS NULL.

Fill in the blank: find the supporters with no gift

SELECT s.name, d.amount
FROM supporters AS s
LEFT JOIN donations AS d
  ON s.id = d.supporter_id
WHERE d.amount ____;

7. Wrap-up

  • A join combines two tables, and its ON condition says which rows go together. One row comes out for each match.
  • INNER JOIN keeps matched rows only. LEFT JOIN keeps every left-table row and fills the gaps with NULL.
  • Find the gaps with IS NULL, never = NULL.
