Every Row Keeps Its Seat

A school sells tickets to its spring play. The teacher wants every seller listed by name, in order, with a place beside each name. Two students sold the same number, and the teacher wants them shown as tied. GROUP BY would fold the names away. A window function keeps every name and adds a place to each one.

1. Four sellers, two homerooms

The table ticket_sales has one row per student. A homeroom is the class a student starts the school day in. The picture shows the table, then what two different queries do with it.

You already know how to sort rows with ORDER BY and summarize them with GROUP BY. This matters because requests like "show where every seller ranks" need the individual rows back, and GROUP BY hands back a summary with no error to warn you.

3. A window function keeps every row

First, the summary the teacher did not ask for:

 homeroom | total_tickets
----------+---------------
 Room 4   |            57
 Room 7   |            45
(2 rows)

The totals are right, but Mia, Theo, Zara and Leo are gone. A window function works differently. It looks across a set of rows and writes one value onto each row, without folding any rows together.

Predict: rank_sellers.sql is the query from the blue side of the picture. Theo and Zara both sold 26. What does rnk show for the two of them?

 student_name | tickets | rnk
--------------+---------+-----
 Mia          |      31 |   1
 Theo         |      26 |   2
 Zara         |      26 |   2
 Leo          |      19 |   4
(4 rows)

The new piece is OVER (ORDER BY tickets DESC). That is the OVER clause: it tells RANK() which rows to look across and in what order. Without it, RANK() would not know what first place means. The parentheses right after RANK stay empty. The last line, ORDER BY rnk, student_name, only sets the order the rows print in; the ORDER BY inside OVER decides the numbers.

AS rnk is an alias: a name you give a result column inside a query. It shows up only in this query's output and changes nothing in the stored table. The rule to remember: GROUP BY replaces rows with a summary, and a window function keeps the rows and adds a value to each.

4. Ties and RANK()

That shared 2 comes from a tie. A tie is two or more rows with the same value in the column you order by. RANK() numbers rows by position, and tied rows share a number.

In the rank_sellers.sql output, why does Leo get 4 and not 3?

So RANK() gives 1, 2, 2, 4. It reports the tie as a tie, then skips the place the tie used up.

5. ROW_NUMBER() never repeats

ROW_NUMBER() gives every row its own number: 1, 2, 3, 4, with no repeats and no skips, even when values are the same. Finish the file to try it.

SELECT student_name, tickets, ROW_NUMBER() ____ (ORDER BY tickets DESC) AS rn FROM ticket_sales;
  1. Type the one keyword that goes between the function's empty parentheses and (ORDER BY ...). It is the same keyword rank_sellers.sql used.
  2. Type only the keyword: no parentheses. Capital letters or lowercase both work.
  3. Press Check. Then the completed query runs.

Your answer is checked. Here is the completed query, running for real:

 student_name | tickets | rn
--------------+---------+----
 Mia          |      31 |  1
 Theo         |      26 |  2
 Zara         |      26 |  3
 Leo          |      19 |  4
(4 rows)

Nothing in the data says Theo beat Zara. Why does Zara get 3 in number_sellers.sql?

Neither function is wrong. RANK() says "these two are equal." ROW_NUMBER() says "you get a clean 1, 2, 3, 4." Pick the one that matches what the report has to promise.

7. Wrap-up

  • GROUP BY replaces rows with a summary. A window function keeps every row and adds a value to each.
  • The OVER (ORDER BY ...) clause tells the function which rows to look across and in what order.
  • RANK() and ROW_NUMBER() only disagree on ties. Choose based on what the report must promise.
