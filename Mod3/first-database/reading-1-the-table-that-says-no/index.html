The Table That Says No

Neighborhood Tool Share lends drills and ladders to neighbors. For two years it kept track in a spreadsheet, and the spreadsheet accepted anything: a blank name, one member typed two ways, dates typed as words. A database can refuse bad data. In this reading you build two tables that say no.

A database is a named container that holds related tables. PostgreSQL is the database system you'll use, and psql is its terminal program: you type SQL, and PostgreSQL answers. Unlike a spreadsheet, PostgreSQL can refuse a row that breaks a rule.

Building tables like these from a blank terminal is often the first task on a new data project. You already know what primary keys and foreign keys are for. Now you type them as real SQL.

3. Create the database and the first table

PostgreSQL only: shown, not run. On your laptop, you first make an empty database named toolshare and connect to it. Type each line in the terminal and press Enter. createdb prints nothing when it works, because many commands are silent when they succeed.

createdb toolshare
psql -d toolshare

A table is one grid inside a database, with named columns. You make one with CREATE TABLE. Each column gets a name, then a data type: the kind of value the column may hold. This reading uses four:

  • INTEGER: a whole number.
  • TEXT: any text.
  • DATE: a calendar date, typed like '2026-03-01' (year, month, day).

After the type, a column can carry a constraint: a rule PostgreSQL checks on every row, every time. NOT NULL refuses a row that leaves this column empty. PRIMARY KEY refuses an empty value or a value another row already has, so every row can be told apart. The picture takes two column definitions apart.

4. A foreign key, and rows that get refused

A FOREIGN KEY is a constraint that only accepts a value already in another table's column. In SQL, you write it with REFERENCES. In create_checkouts.sql, every member_id must already exist in members. That is also why members had to be created first: a reference can't point at a table that isn't there yet.

Each error names the rule that refused the row. The fix is to supply a real value, not to remove the rule. PostgreSQL words these errors a little differently:

PostgreSQL only: shown, not run. The same two inserts in psql print these errors. Relation is PostgreSQL's word for a table.

ERROR:  null value in column "tool_name" of relation "checkouts" violates not-null constraint
ERROR:  insert or update on table "checkouts" violates foreign key constraint "checkouts_member_id_fkey"
DETAIL:  Key (member_id)=(12) is not present in table "members".

5. Ask a question with SELECT, WHERE, and ORDER BY

A query asks a table a question. SELECT lists the columns to show, and SELECT * means every column. FROM names the table. WHERE keeps only the rows where a condition is true. ORDER BY sorts the rows. For dates, that means oldest first, and adding DESC after the column sorts newest first.

7. Wrap-up

  • createdb makes the database, and CREATE TABLE gives each column a name, a data type, and its constraints.
  • NOT NULL, PRIMARY KEY, and FOREIGN KEY make PostgreSQL refuse bad rows with an error that names the rule.
  • SELECT picks columns, WHERE picks rows, and ORDER BY sorts them.
