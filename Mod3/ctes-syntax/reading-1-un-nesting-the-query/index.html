Un-Nesting the Query

A teacher runs a summer reading challenge. Each week, every student logs how many pages they read. The teacher asks: which students read more pages than the average student? One SQL query answers it. Written with nested subqueries, you read it from the inside out. Written as a CTE, you read it from top to bottom.

3. A CTE gives a step a name

A CTE (common table expression) is a named, temporary result. You define it at the top of a query, then use it later in the same query as if it were a table. The WITH clause is what defines it:

WITH name AS ( a complete SELECT query ) the main query, which can use name like a table

The named step is a named intermediate result: one step of a bigger calculation, with its own label instead of being an unnamed block inside another block.

Predict: heavy_weeks.sql names the rows where a student read 50 pages or more, then counts them. What number does it return?

 COUNT(*)
----------
        3
(1 row)
  1. Look at the pages column in the table in section 1. Count the rows with 50 or more. Those are the rows heavy_weeks keeps.
  2. Type only the number, like 5.
  3. Press Check. Then the query runs so you can compare.

4. Rewrite a subquery as a CTE

A subquery is a complete SELECT written inside parentheses inside another query. Here is the teacher's question, "who read more than the average student?", written with two nested subqueries:

 student_name | total_pages
--------------+-------------
 Ana          |          95
 Cleo         |         130
(2 rows)

The answer is right. But to know what HAVING compares against, you first find the innermost parentheses (each student's total), then the average of those totals, then carry that back up to HAVING. You read it from the inside out.

Predict: above_average_cte.sql names each student's total first. What does it return?

 student_name | total_pages
--------------+-------------
 Ana          |          95
 Cleo         |         130
(2 rows)

Notice that student_totals is used twice: once in FROM, and once inside AVG(). The step is written once and used twice.

Readability is how easily someone else can trust a query at a glance, without running it. Being correct and being readable are separate: both queries above are correct.

Which query is easier to read, and why?

5. Your turn, and how long a name lasts

A new question: which weeks had more total pages than the average week? Here is the CTE version with two keywords missing:

____(1) week_sums AS ( SELECT week_ending, SUM(pages) AS week_total FROM reading_log GROUP BY week_ending ) SELECT week_ending, week_total FROM week_sums ____(2) week_total > (SELECT AVG(week_total) FROM week_sums);
  1. In box (1), type the one keyword that starts every CTE. Capital letters or lowercase both work.
  2. In box (2), type the one keyword that filters rows in the main query. The main query has no GROUP BY of its own, and week_total is already a plain column of week_sums.
  3. Press Check my rewrite. The page tells you which blank, if any, needs another look.

Your answer is checked. Here is the completed query, running for real:

 week_ending | week_total
-------------+------------
 2026-07-10  |        190
(1 row)

Scope is how far a name reaches. A CTE's name belongs to the one query it is attached to. When that query ends at its semicolon, the name is gone. It is never saved as a table.

Predict: scope.sql has two statements. The second one is the last line. What happens when the database reaches it?

Error: no such table: student_totals

SQL stops at the error, so only the error shows. PostgreSQL words it a little differently: relation "student_totals" does not exist.

7. Wrap-up

  • A CTE names one step with WITH name AS (...) at the top, so the query reads top to bottom.
  • A CTE and a subquery can return the same rows. The CTE is easier for someone else to check.
  • A CTE's name can be used more than once, but only inside its own query.

New situation: the teacher's next question is which students had a best week above the average best week. A classmate wrote it with a subquery inside a subquery. What should you do first to make it easier to read?

In interviews: you may get a nested query and the question "how would you make this easier to review?" Naming the inner step with a CTE is a strong first answer.

Where this goes next: one WITH clause can hold several named steps in a row, each one using the step before it.
