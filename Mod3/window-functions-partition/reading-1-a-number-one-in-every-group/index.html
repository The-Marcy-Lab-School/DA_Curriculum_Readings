A Number One in Every Depot

A delivery company ranks all its drivers by how many packages they delivered last month. One name lands on top. Then the manager asks a different question: who is the best driver at each depot? The company wants to give one award per depot. That takes a ranking that starts over inside each group.

3. PARTITION BY starts the count over

Here is the manager's first query. It ranks everyone against everyone:

     name      |   depot   | packages | rnk
---------------+-----------+----------+-----
 Tasha Boone   | Riverside |      412 |   1
 Priya Nadar   | Eastgate  |      401 |   2
 Omar Reyes    | Riverside |      388 |   3
 Luis Ferrer   | Eastgate  |      372 |   4
 Grace Okafor  | Hillcrest |      366 |   5
 Dee Whitfield | Riverside |      355 |   6
 Sam Beckett   | Hillcrest |      344 |   7
(7 rows)

RANK() is a window function: it looks at a set of other rows while it works out a value for the current row, and it keeps every row. The OVER clause, the OVER (...) part, says which rows it may look at and in what order. Right now it looks at the whole table.

PARTITION BY goes inside the OVER (...) parentheses, before ORDER BY. It splits the rows into groups first, and the ranking starts over at 1 inside each group. Each group is called a partition. Here, one partition is one depot's drivers.

Fill in the blank: rank inside each depot

SELECT name, depot, packages, RANK() OVER (____ depot ORDER BY packages DESC) AS rnk FROM driver_month ORDER BY depot, rnk;

4. PARTITION BY is not GROUP BY

Both words sound like "make groups," but they do opposite things to your row count.

Predict: depot_max.sql uses GROUP BY depot. What does it return?

   depot   | most_packages
-----------+---------------
 Eastgate  |           401
 Hillcrest |           366
 Riverside |           412
(3 rows)

GROUP BY depot squeezes the table down to one row per depot, and the names are gone. PARTITION BY depot never removes a row. It only changes which rows each rank is compared against.

5. Keep only the winners

The manager wants the three winners and nothing else. The first try adds a filter to the end of the query.

Predict: what happens when winners_try.sql runs?

Error: misuse of aliased window function rnk

The database does not run a query in the order it is written. It gathers rows from FROM, then throws out rows that fail WHERE, then works out the SELECT list, where RANK() runs. So when WHERE runs, rnk does not exist yet. The browser's SQL says "misuse of aliased window function rnk"; PostgreSQL says column "rnk" does not exist. Same mistake, slightly different wording. (HAVING also runs before the SELECT list, so it fails the same way.)

The fix is to finish the ranking first. A CTE (common table expression) is a WITH name AS (...) block that runs a query, names its finished result, and lets the rest of the statement select from that name. Outside the CTE, rnk is an ordinary column:

     name     |   depot   | packages
--------------+-----------+----------
 Priya Nadar  | Eastgate  |      401
 Grace Okafor | Hillcrest |      366
 Tasha Boone  | Riverside |      412
(3 rows)

Three rows, one award per depot. This shape has a name: top-N per group, a query that returns the highest-ranked rows inside each group instead of only the highest overall. "Best driver per depot" is a top-1 per group question.

7. Wrap-up

  • PARTITION BY inside OVER (...) splits rows into groups, and the ranking starts over in each group. Every row stays.
  • GROUP BY folds rows together; PARTITION BY never does.
  • A window function runs after WHERE, so rank inside a CTE and filter in the outer query.

New situation: next month the company gives awards to the top two drivers at each depot. Starting from winners.sql, what is the only change you need?

In interviews: "the top two in each department" is the same top-N per group question. Say the plan out loud: rank with PARTITION BY, wrap it in a CTE, then filter on the rank.

Where this goes next: PARTITION BY works with other window functions too, such as each driver's own depot average shown beside their total.
