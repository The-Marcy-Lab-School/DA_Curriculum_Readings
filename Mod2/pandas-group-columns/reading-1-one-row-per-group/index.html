One Row Per Group

A nonprofit runs blood drives at a library, a community center and a fire station. A volunteer writes one row per drive. A unit is one bag of donated blood. The team asks, "Which place collects the most blood?" Eight rows are easy to read by eye. Eight hundred are not.

2. One row per group with groupby

Here is the nonprofit's file, drives.csv. One Community Center drive has a blank units value.

site,donors,units,volunteer_hours Library,30,26,10 Community Center,45,40,12 Fire Station,22,20,8 Library,34,31,10 Community Center,50,,12 Fire Station,25,24,8 Library,28,25,9 Community Center,41,36,11
import pandas as pd
drives = pd.read_csv("drives.csv")
drives.shape
(8, 4)

To compare sites, you could write one filter per site. groupby does it in one line. It splits the rows into one pile per site, applies a summary to each pile, and combines the answers into one row per site.

New in this cell: drives.groupby("site") makes the piles. On its own it shows no table, only a GroupBy object. ["units"] picks the column to summarize. .agg(["count", "mean", "median"]) works out all three summaries for each pile at once. .round(1) rounds to one decimal place.

Predict: Community Center held 3 drives. What will its count be in cell [2]?

drives.groupby("site")["units"].agg(["count", "mean", "median"]).round(1)
                  count  mean  median
site
Community Center      2  38.0    38.0
Fire Station          2  22.0    22.0
Library               3  27.3    26.0

Read the line left to right: group by site, pick units, take the summaries. Each summary is an aggregation. Keep count next to the mean: it shows how many rows each number rests on, so you can spot a group too small to trust. Mean and median side by side are a quick skew check. They are close at every site, so no single drive is pulling a mean.

3. Build new columns

A derived column is worked out from columns you already have. You write the formula once, and pandas applies it to every row at once, with no loop. A column can also start with the same value in every row.

Predict: what will units_per_hour be in row 4, the drive with no units?

drives["units_per_hour"] = drives["units"] / drives["volunteer_hours"]
drives["goal_met"] = "no"
drives[["site", "units", "units_per_hour", "goal_met"]].round(1)
               site  units  units_per_hour goal_met
0           Library   26.0             2.6       no
1  Community Center   40.0             3.3       no
2      Fire Station   20.0             2.5       no
3           Library   31.0             3.1       no
4  Community Center    NaN             NaN       no
5      Fire Station   24.0             3.0       no
6           Library   25.0             2.8       no
7  Community Center   36.0             3.3       no

Fire Station collects the fewest units. But per volunteer hour, its drives (2.5 and 3.0) are close to the Library's (2.6 to 3.1). A new column can show what the raw counts hide.

4. Change rows the safe way

The team counts a drive as meeting its goal at 30 units or more. A saved True/False mask marks those drives. Here is a rule to remember: a filter gives you a copy. In pandas 3, drives[big] is a separate table. Changing it never touches drives.

Predict: cell [4] tries to set goal_met to "yes" in two steps. How many "yes" values will drives have?

big = drives["units"] >= 30
drives[big]["goal_met"] = "yes"
(drives["goal_met"] == "yes").sum()
np.int64(0)

pandas also shows this warning when cell [4] runs (shortened):

ChainedAssignmentError: A value is being set on a copy of a DataFrame or Series through chained assignment. Try using '.loc[row_indexer, col_indexer] = value' instead, to perform the assignment in a single step.

This is chained assignment: drives[big] makes a copy, and ["goal_met"] = "yes" changes the copy. Despite its name, ChainedAssignmentError is a warning. The cell keeps running, so it is easy to miss, and every count after it is quietly wrong. Older tutorials suggest adding .copy(). That still changes a copy.

New in this cell: drives.loc[rows, column] = value names the rows and the column inside one pair of brackets. pandas then changes drives itself, in one step. Cell [5] uses it with the same big mask.

  1. Look at the units column in drives.csv. Count the drives where big is True: 30 units or more.
  2. Type how many "yes" values cell [5] will show. Type only a number.
  3. Press Check, then run cell [5].

Why: a cleaning step that silently does nothing is worse than a crash, so check the count after every change.

drives.loc[big, "goal_met"] = "yes"
(drives["goal_met"] == "yes").sum()
np.int64(3)

Three drives reached 30 units. The drive with a blank units value stays "no", because a blank is never >= 30.

5. Add columns from a lookup table

The team wants each site's neighborhood next to its drives. A lookup table holds one row per site. A merge matches rows on a shared key column, here site, and copies the lookup's columns over.

New in this cell: pd.DataFrame({...}) builds a small table from a dict of lists. drives.merge(lookup, on="site", how="left") matches on site. how="left" keeps every row of drives, and a row with no match gets NaN.

Predict: the lookup in cell [6] spells one site "Firehouse". What will the checks show?

lookup = pd.DataFrame({
    "site": ["Library", "Community Center", "Firehouse"],
    "neighborhood": ["Northside", "Riverside", "Hillcrest"],
})
merged = drives.merge(lookup, on="site", how="left")
print("rows before:", len(drives))
print("rows after: ", len(merged))
merged["neighborhood"].isna().sum()
rows before: 8
rows after:  8
np.int64(2)

Keys must match exactly, letter for letter. The merge ran with no error, and only the checks showed the problem. Run two checks after every merge: rows before and after, and blanks in the new column. With the key spelled the same way in both tables, the blanks go away:

lookup = pd.DataFrame({
    "site": ["Library", "Community Center", "Fire Station"],
    "neighborhood": ["Northside", "Riverside", "Hillcrest"],
})
merged = drives.merge(lookup, on="site", how="left")
merged["neighborhood"].isna().sum()
np.int64(0)

7. Wrap-up

  • groupby splits rows by a category, applies summaries, and combines them into one row per group. Keep count next to the mean and median.
  • A filter gives you a copy. To change rows in the original, use .loc[rows, column] = value in one step.
  • After a merge, check the row count and the blanks in the new column. Keys must match exactly.

New situation: next season, the nonprofit adds drives at a Rec Center. The lookup table has no Rec Center row. After drives.merge(lookup, on="site", how="left"), what happens to the Rec Center drives?

In interviews, "What does .groupby() do, step by step?" is a common question. A clear answer covers four parts: what the code is for, how it works, what it returns, and one edge case, such as blanks it skips.
